# 第 9 章：队列及其应用

上一章的栈只在同一端进出，遵循“后进先出”；本章的队列从**队尾入队**、从**队首出队**，遵循“先进先出”（FIFO，first in, first out）。这种看似简单的顺序限制，让“按到达顺序等待”和“按距离一层层扩展”有了自然的数据结构。建议先读队列 ADT 与两种存储，再运行演示，最后逐一推演列车、电路、图元和工厂仿真。

## 1. 队列抽象数据类型（ADT）

队列仍是一个有位置顺序的线性表，但只允许在两端做指定操作。`queue.hpp` 定义以下行为：

| 操作 | 含义 | 空队列时 |
| --- | --- | --- |
| `empty()` / `size()` | 是否为空 / 元素个数 | 返回 `true` / `0` |
| `front()` | 查看最早入队的元素，不删除 | 抛 `queueEmpty` |
| `back()` | 查看最近入队的元素，不删除 | 抛 `queueEmpty` |
| `push(x)` | 把 `x` 加到队尾 | 变成唯一元素 |
| `pop()` | 删除队首，不返回它 | 抛 `queueEmpty` |

```text
push(10), push(20), push(30)
队首 → [10] [20] [30] ← 队尾
front()=10，back()=30；pop() 后队首变成 20。
```

若要保留将出队的值，先复制 `front()`，再调用 `pop()`。接口提供 const 与非 const 的首尾访问。不要把“最先进入”和“编号最小”混为一谈：队列本身**不排序**，只是保留进入顺序。

## 2. 数组描述：环形缓冲区 `arrayQueue`

`arrayQueue.hpp` 使用一块连续数组、`head`（队首所在槽位）、`size`（有效元素数）与 `capacity`。逻辑第 `k` 个元素在 `(head+k)%capacity`；新元素放到 `(head+size)%capacity`。出队仅让 `head` 前进一格，数组前方空出来的槽位将来可以再次使用：

```text
容量 5，物理下标： 0    1    2    3    4
物理内容：       [D]  [ ]  [ ]  [B]  [C]
队首 head=3，size=3；逻辑顺序 B → C → D；下次入队在 (3+3)%5=1。
```

**判断环形队列正确性的办法是从 `head` 连续走 `size` 次，看看是否依次得到预期的 FIFO 顺序。**

本实现明确记录 `size`，因此 `size==0` 为空，`size==capacity` 为满；容量 1 也能存一个元素。原代码只用前后下标判断空满，必须浪费一个槽位，而且容量 1 会出现混淆。满时新容量加倍，并从逻辑队首开始复制到新数组的 `0..size-1`，随后 `head=0`；这样无论旧数组是否环绕，都保持顺序。

代码使用 C++11 的 `std::allocator<T>` 只为**有效元素**构造对象：出队会立即析构那个元素，空槽位不要求 `T` 有默认构造函数。这也避免了原实现对 `new T[]` 的元素手动析构、最后又 `delete[]` 的重复析构问题。扩容时若复制失败，旧队列仍保持原状；复制构造和赋值创建独立存储。

`front`、`back`、`pop` 为 `O(1)`；`push` 平常为 `O(1)`，一次扩容为 `O(n)`，连续入队均摊 `O(1)`。数组占用 `O(capacity)` 存储空间。扩容会使原有元素的引用失效；不要跨入队操作长期保存 `front()` 或 `back()` 的引用。

## 3. 链表描述：首尾指针 `linkedQueue`

`linkedQueue.hpp` 用第 6 章的单链结点：首指针指向出队端，尾指针指向入队端。

```text
frontNode → [10|next] → [20|next] → [30|null] ← backNode
```

入队先构造新结点，再让原尾结点指向它；空队列时新结点同时是首与尾。出队删除首结点并前移首指针；**删掉最后一个元素时必须把尾指针也清空**，否则尾指针会悬空。新版实现深拷贝、赋值与清理，避免复制两个队列后共享同一条链。`front`、`back`、`push`、`pop` 都是 `O(1)`，但每次入队要分配一个结点，每个元素还需要一个链接指针；总空间 `O(n)`。

| 选择 | 数组队列 | 链队列 |
| --- | --- | --- |
| 存储 | 连续环形数组，可能预留空槽 | 分散结点，按需分配 |
| 入队 | 均摊 `O(1)`，扩容一次 `O(n)` | `O(1)`，每次新建结点 |
| 出队与首尾访问 | `O(1)` | `O(1)` |
| 引用稳定性 | 扩容会移动元素 | 未删除的结点不因入队整体搬移 |

## 4. 应用一：列车车厢重排——缓冲轨道也是队列

与第 8 章的**栈式**缓冲轨道不同，这里每条轨道从一端进入、另一端离开，因而是 FIFO 队列。目标仍是把输入排列输出为 `1,2,…,n`。`railroad.hpp` 的 `rearrangeRailroadWithQueues(input,k)` 不用全局变量，返回成功与否、搬移记录，以及失败时下一个尚待输出的编号。

一条轨道若已有 `3,4`（队首到队尾），可先出 `3` 再出 `4`；若把 `2` 放在 `4` 后，`2` 会被挡住。因此**每条非空轨道从队首到队尾严格递增**。当前车厢 `c` 只有在 `back<c` 时才能进入该轨道。

以 `[3,4,2,1]`、两条缓冲轨道为例：

| 下一辆输入 | 轨道 1（首→尾） | 轨道 2（首→尾） | 已输出 |
| --- | --- | --- | --- |
| 3 | `[3]` | `[]` | `[]` |
| 4 | `[3,4]` | `[]` | `[]` |
| 2 | `[3,4]` | `[2]` | `[]` |
| 1 | `[3,4]` | `[2]` | `[1]` |
| 连续检查各队首 | `[]` | `[]` | `[1,2,3,4]` |

若只有一条轨道，`2` 不能排在 `[3,4]` 后面，又不能直接输出，于是失败。算法维护 `nextNeeded`：输入车厢正好等于它就直接输出，并反复检查各轨道**队首**能否紧接着输出。否则选 `back<c` 且 `back` 最大的轨道（最贴近 `c` 的较小尾值）；若没有，选第一条空轨道；再无选择则失败。这维持轨道递增不变量，也尽量保留小尾值轨道给后续较小编号。

每辆车最多进入并离开缓冲轨道各一次；选轨道、寻找可出的队首最多扫描 `k` 条轨道，所以时间 `O(nk)`、空间 `O(n+k)`（含轨道和搬移记录）。测试将 `n≤5` 的所有排列、`k=0..3` 的贪心结果与穷举所有可放轨道选择的参照结果比较。

## 5. 应用二：电路布线——Lee 波前与最短路径

`circuitRouting.hpp` 把电路板看成矩形网格：`0` 可通行，`1` 是障碍；只允许上下左右四邻接，每走一格代价相同。队列保存**已到达但尚未扩展邻格**的位置：

```text
起点入队（距离 0）
出队距离 0 的格子，发现并入队距离 1 的格子
再出队距离 1 的格子，发现距离 2 的格子……
```

由于先发现的格子先出队，距离 `d` 的所有格子会在距离 `d+1` 的格子前被扩展。**第一次到达终点就是最少步数路径。**这与第 8 章迷宫 DFS 只保证找到某一条路径的目标不同。代码在邻格**入队时**标记已访问，防止多个方向重复入队；同时记下父格，终点找到后沿父格反向回溯，再反转得到起点到终点的路径。无路可走返回空路径。

若有 `r×c` 个格子，每格至多入队一次，时间与空间均为 `O(rc)`。这是单条线路、等权四邻接的教学模型；多条线路之间互相占位、拐弯惩罚或多层布线需要额外规则。

## 6. 应用三：图元识别——队列式连通区域标号

`imageComponents.hpp` 把二值图像的 `1` 当作前景、`0` 当作背景。扫描到尚未标号的前景像素，就创建一个新图元编号，把它入队；每次出队一个像素，再把与它相邻且未标号的前景像素标成同一编号并入队。队列耗尽时，整个连通区域都已找到，接着继续扫描图像。返回标签矩阵及每个图元的像素数。

```text
1 0 1
0 1 0
1 0 1
```

若只算上下左右的**四连通**，上图有 5 个单像素图元；若也算对角线的**八连通**，则五个像素属于一个图元。连通规则必须先讲清，否则“有几个图元”没有唯一答案。像素在**入队时**标记，避免被两个已处理邻居重复发现。每个像素及其常数个邻居最多检查一次，时间 `O(rc)`，标签与队列空间 `O(rc)`。

## 7. 应用四：工厂仿真——按事件推进时间

`factorySimulation.hpp` 建模为多台**相同机器**共用一条 FIFO 等待队列。每个任务有 `id`、到达时刻、加工时长；任务一旦开始就连续加工到结束，不抢占。相同到达时刻按输入顺序排队；有机器空闲时，优先取等待最久的任务。机器编号从 1 开始。

不必让时钟一格一格地空转。只需跳到下一次**任务到达**或**机器完成**的时刻：

1. 释放这个时刻完成的机器。
2. 把这个时刻到达的任务按原顺序入队。
3. 按机器编号从小到大，把等待队首交给空闲机器。
4. 记录开始、结束与等待时间；继续跳到下一事件。

例如任务 `(编号,到达,时长)` 为 `(1,0,3),(2,1,2),(3,1,1)`，两台机器：

| 时刻 | 事件 | 等待队列 | 机器状态 |
| --- | --- | --- | --- |
| 0 | 任务 1 到达 | 空 | 机器 1 加工 1，结束于 3 |
| 1 | 任务 2、3 到达 | `[3]` | 机器 2 加工 2，结束于 3 |
| 3 | 两台机器完成 | 空 | 机器 1 加工 3，结束于 4 |

任务 3 等了 `3-1=2` 个时间单位；全部任务的平均等待时间是 `(0+0+2)/3=2/3`，完工时刻（makespan）为 `4`。`utilization` 以所有机器忙碌时间除以 `机器数×完工时刻`。代码先按到达时刻稳定排序；每次找下一完成事件与分配空闲机器都扫描 `m` 台机器，若有 `n` 个任务，时间为 `O(n log n+nm)`，空间 `O(n+m)`。这是基础排队仿真；任务优先级、不同机器能力、故障或任务依赖不在该模型中。

## 8. 原代码中修复了什么？

- 原环形数组队列只靠前后下标区分空满，容量为 1 时不可靠；扩容后队首、队尾重定位也有问题。新版显式保存元素数并按逻辑顺序扩容。
- 原 `arrayQueue::pop` 手动析构 `new T[]` 的槽位，随后数组释放可能再次析构。新版只构造有效元素，并在出队时销毁。
- 原链队列未实现深拷贝，删掉最后一个结点后尾指针可能悬空。新版维护“空队列首尾均空”的不变量。
- 原列车代码依赖全局轨道状态，扫描轨道时还把车厢数当作轨道数使用。新版每次调用拥有自己的状态，并验证输入排列。
