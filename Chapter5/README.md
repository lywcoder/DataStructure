# 第 5 章：线性表的数组描述

本章的学习目标是分清**线性表是什么**与**数组怎样实现它**，然后能自己解释查找、插入、删除和扩容的过程及复杂度。建议先读第 1～4 节，再对照 `arrayList.hpp`，最后运行 `testArrayLists.cpp`。

## 1. 什么是线性表？

线性表（linear list）是一个有**位置顺序**的有限元素序列：`(a₀, a₁, ..., aₙ₋₁)`。`n` 是长度；空表的 `n = 0`。除首元素外，每个元素有一个直接前驱；除尾元素外，每个元素有一个直接后继。这里的“顺序”是**位置顺序**，并不要求数值已经排序；`[8, 3, 8]` 也是线性表，而且允许重复值。

例如在 `[10, 20, 30]` 的下标 `1` 插入 `15`，得到 `[10, 15, 20, 30]`。删除下标 `2` 后得到 `[10, 15, 30]`。这两个操作都需要保留其他元素原有的相对次序。

`linearList.hpp` 定义的是**抽象数据类型（ADT）**：它规定能做哪些事，不规定元素怎样放在内存中。核心操作如下：

| 操作 | 含义 | 下标范围 |
| --- | --- | --- |
| `empty()`、`size()` | 是否为空、当前元素个数 | 无 |
| `get(i)` / `at(i)` | 取得第 `i` 个元素 | `0 ≤ i < size` |
| `indexOf(x)` | 返回 `x` 首次出现的下标，找不到返回 `-1` | 无 |
| `insert(i, x)` | 在第 `i` 个位置插入，后续元素右移 | `0 ≤ i ≤ size` |
| `erase(i)` | 删除第 `i` 个元素，后续元素左移 | `0 ≤ i < size` |
| `output(out)` | 按位置顺序输出到指定流 | 无 |

**思考：** 为什么插入允许 `i == size`，而读取和删除不允许？因为 `size` 正好是尾部后面的新位置，却不是已经存在的元素位置。

## 2. 用连续数组描述线性表

`arrayList.hpp` 用一段连续数组存储元素，维护三个状态：`element` 指向数组、`listSize` 是有效元素数、`arrayLength` 是数组容量。始终保持 `0 ≤ listSize ≤ arrayLength`；有效元素只在下标 `[0, listSize)` 中。

```text
下标：       0      1      2      3      4      5
数组：      [10]   [20]   [30]   [ ? ]  [ ? ]  [ ? ]
                  有效区 n = 3       预留槽位
容量 capacity = 6
```

预留槽位不能通过 `get` 访问。教材式 `new T[capacity]` 实际上已构造全部槽位，但逻辑上只有前 `size` 个属于线性表。`size` 是表的长度，`capacity` 是当前可容纳的元素数，二者不能混用。

数组元素连续，若首地址是 `base`，单个元素占 `sizeof(T)` 字节，第 `i` 个元素的位置可由 `base + i × sizeof(T)` 算出。因此**已知下标时**能直接定位，`get(i)` 为 `Θ(1)`；但按值找 `x` 时一般仍要逐个比较，最坏为 `Θ(n)`。数组连续不等于所有查找都快。

## 3. 插入和删除为什么需要移动？

在 `[10, 20, 30]` 的位置 `1` 插入 `15`，要先从右往左移动，避免覆盖尚未搬走的值：

```text
初始： [10, 20, 30, _]
移动： [10, 20, 30, 30]  // 30 右移
移动： [10, 20, 20, 30]  // 20 右移
写入： [10, 15, 20, 30]
```

从右到左移动是关键。如果先把 `20` 覆盖掉，再想复制它就晚了。删除位置 `1` 则反过来，从左往右覆盖：`[10, 20, 30] → [10, 30, 30]`，然后把逻辑长度减到 `2`。最后一个槽位可能仍保存旧值，但已经**不属于**线性表。

因此，尾部插入在容量足够时不需要移动元素；头部或中间插入最多移动 `n` 个元素。删除尾部只改长度，删除头部最多移动 `n-1` 个元素。这些操作保持未删元素的先后顺序。

## 4. 容量不够时如何扩容？

当 `size == capacity`，`arrayList` 分配一块两倍容量的新数组，把旧元素复制过去，再插入新元素，最后释放旧数组。示意：`2 → 4 → 8 → 16`。扩容的一次插入需要复制 `Θ(n)` 个元素，且旧元素的引用和迭代器都会失效。

为何还说**尾部追加均摊 `O(1)`**？从空表连续追加 `n` 次，扩容时累计复制量至多近似 `1 + 2 + 4 + ... < 2n`，再加上 `n` 次写入，总工作量仍是 `O(n)`；平均分摊到每次追加是 `O(1)`。这不是说每次追加都一定只花常数时间。对指定位置 `i` 的插入仍需移动后缀，最坏 `Θ(n)`。

扩容后 `size` 不变，`capacity` 变大；删除元素时本实现不自动缩容，避免频繁增删时反复重新分配。

## 5. 操作复杂度表

令 `n = size`、`c = capacity`，将一次元素比较、复制和赋值视为常数时间；若 `T` 的这些操作很昂贵，还需另计其成本。

| 操作 | 最好 | 最坏 | 原因 |
| --- | --- | --- | --- |
| `empty`、`size`、`capacity` | `Θ(1)` | `Θ(1)` | 读取已有状态 |
| `get(i)` / `at(i)` | `Θ(1)` | `Θ(1)` | 用下标直接定位 |
| `indexOf(x)` | `Θ(1)` | `Θ(n)` | 可能首次命中，也可能检查全部元素 |
| 尾部 `insert(n, x)` | `Θ(1)` | `Θ(n)` | 扩容那次要复制旧元素；连续追加均摊 `O(1)` |
| 任意位置 `insert(i, x)` | `Θ(1)` | `Θ(n)` | 右移后缀，满时还要扩容 |
| 尾部 `erase(n-1)` | `Θ(1)` | `Θ(1)` | 仅减少逻辑长度 |
| 任意位置 `erase(i)` | `Θ(1)` | `Θ(n)` | 左移后缀 |
| `output(out)`、遍历 | `Θ(n)` | `Θ(n)` | 每个有效元素访问一次 |

`arrayList` 为容量 `c` 分配数组，存储空间为 `Θ(c)`；由于 `new T[c]` 会默认构造全部槽位，初始化和复制构造也会付出与容量有关的成本。表中 `erase` 的 `Θ(1)` 只表示尾部删除的逻辑操作：这份教材式实现不会立即销毁尾部未使用槽位里的对象，而是在该槽位被覆盖或整个数组释放时处理。若需要标准容器那样精确的元素生命周期，应使用 `std::vector` 或更复杂的原始存储管理。

## 6. 两个实现分别教什么？

- `arrayList.hpp`：亲手管理 `new[]` 分配的连续数组，观察长度、容量、搬移、倍增扩容和深拷贝。它为了教学保持简单，要求 `T` 可默认构造、复制构造及赋值。
- `vector.hpp` 中的 `vectorList`：使用 `std::vector<T>` 保存连续元素，实现同一个 ADT。标准库负责分配、元素生命期和拷贝；`reserve(initialCapacity)` 只预留容量，**不会创建那么多个有效元素**。因此它可以存放没有默认构造函数的类型。

两个类都实现了抽象接口中的虚函数 `indexOf` 和 `output`。因此实例化这些容器时，`T` 还应支持相等比较 `==` 和流输出 `<<`，即使当前代码暂时不调用这两个操作；测试中的无默认构造类型也提供了这两个运算。

两者的查找、插入、删除的主要时间量级相同。学习原理时读 `arrayList`；写普通应用代码时通常直接选 `std::vector`。`vectorList` 是为了对照接口与实现而保留的包装，并没有比 `std::vector` 增加新的数组算法。

教材接口 `linearList::get(int) const` 返回 `T&`，意味着从 `const` 线性表也能取得可写引用，这不符合通常的 const 约定。为兼容后续章节的链表代码，本章保留该签名；两个数组实现都额外提供 `at(i)` 的可写与只读重载。只读访问请使用 `const` 对象的 `at(i)` 或 `begin()`。

## 7. 迭代器、复制和异常

数组的 `T*` 本身满足随机访问迭代器要求。因此 `iterator.hpp` 用指针类型别名，`arrayList.begin()` 指向首元素，`end()` 指向最后一个有效元素的后面；可用于范围 `for` 和 `std::sort`。`end()` 是边界，**不能解引用**。插入导致扩容时，所有旧指针、引用和迭代器失效；即使未扩容，插入或删除位置及其后面的迭代器也不能继续按旧含义使用。

`arrayList` 实现了析构、深拷贝构造和拷贝赋值：复制品拥有自己的数组，改副本不会改原表。插入时先保存待插入值，因此 `list.insert(0, list.at(2))` 即使发生搬移或扩容也能得到原来的值。扩容与拷贝赋值使用临时对象保护原表；若元素在**原数组内搬移**时赋值抛出异常，表仍保持合法容量和长度，但部分值可能已经改变，这不是强异常保证。

非法初始容量抛 `std::invalid_argument`；越界的访问、插入或删除抛 `std::out_of_range`。这些异常与空表的 `indexOf(x) == -1` 是不同情况。

原始 Chapter5 代码中的主要问题包括：`erase` 对 `new T[]` 的元素手动调用析构导致以后可能重复析构；`insert` 依赖未提供的扩容函数；复制构造和默认赋值不可靠；`output(out)` 实际写到 `std::cout`；`vectorList` 的插入等方法未完成；自定义迭代器中的全局 `copy` 容易与标准算法混淆。现在两个头文件可独立包含并配有头文件保护。

## 8. 动手运行与自查

下面的短例子可以放进自己的 `.cpp`，从 `Chapter5` 目录编译：

```cpp
#include "arrayList.hpp"
#include <iostream>

int main() {
    arrayList<int> scores(2);
    scores.insert(0, 10);             // [10]
    scores.insert(1, 30);             // [10, 30]
    scores.insert(1, 20);             // [10, 20, 30]，容量不足时扩容
    std::cout << scores << '\n';      // 10 20 30
    scores.erase(0);                  // [20, 30]
    std::cout << scores.at(0) << '\n';// 20
}
```

运行配套测试（含基本操作、越界、别名插入、深拷贝、迭代器，以及 3000 步随机操作与 `std::vector` 的逐步对照）：

```powershell
g++ -std=c++11 -Wall -Wextra -Wpedantic -Werror testArrayLists.cpp -o testArrayLists.exe
.\testArrayLists.exe
```

测试通过时没有输出。测试使用 `assert`，不要加 `-DNDEBUG`。可以自己尝试三个问题：① 向下标 `0` 插入时为什么要从右向左搬？② 长度为 5、容量为 8 的表尾部插入是否扩容？③ 为什么 `indexOf` 不会因为使用数组就自动变成 `O(1)`？答案分别对应第 3、4、2 节。
