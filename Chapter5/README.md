# 第 5 章：线性表 ADT 与连续数组实现

本章第一次完整区分“抽象数据类型规定什么”和“具体存储怎样做到”。线性表描述位置顺序；`arrayList` 与 `vectorList` 都实现相同操作，却在元素生命期、类型要求和异常安全上采用不同机制。

## 1. 学习目标与先修知识

先修第 3 章的复杂度分析、第 4 章的连续访问局部性，以及 C++ 的类、模板、动态数组、引用与异常。学完后应能：

1. 写出线性表 ADT 的语义和合法下标范围。
2. 维护 `0 <= size <= capacity` 与有效区间 `[0,size)`。
3. 手算连续数组中插入、删除、查找和扩容的移动过程。
4. 区分单次最坏成本与倍增扩容的均摊成本。
5. 解释深复制、赋值、自赋值、迭代器失效和元素生命期。
6. 比较教材式 `new T[]` 实现与 `std::vector` 封装的类型约束。

阅读顺序：先读 [`linearList.hpp`](./linearList.hpp)，再读 [`arrayList.hpp`](./arrayList.hpp) 和 [`vector.hpp`](./vector.hpp)，最后读 [`testArrayLists.cpp`](./testArrayLists.cpp)。[`iterator.hpp`](./iterator.hpp) 是数组指针风格迭代器的轻量包装。

## 2. 线性表是什么

线性表是有限序列：

```text
(a0, a1, ..., a(n-1))
```

顺序表示**位置关系**，不要求按键排序；允许重复值。`[8,3,8]` 是长度 3 的线性表。核心操作：

| 操作 | 语义 | 合法位置 |
| --- | --- | --- |
| `empty()` | 是否没有元素 | 无 |
| `size()` | 元素个数 | 无 |
| `at(i)` / `get(i)` | 访问第 `i` 个元素 | `0 <= i < size` |
| `indexOf(x)` | 第一个等价值的位置，找不到为 `-1` | 无 |
| `insert(i,x)` | 在位置 `i` 前插入 | `0 <= i <= size` |
| `erase(i)` | 删除已有位置 `i` | `0 <= i < size` |
| `output(out)` | 按位置输出 | 无 |

插入允许 `i==size`，因为它表示追加到尾后；访问与删除不允许，因为该位置尚无元素。

[`linearList.hpp`](./linearList.hpp) 只规定虚函数接口。它不承诺连续内存、容量、常数时间随机访问或具体异常类型；这些属于实现契约。

## 3. 连续数组的表示不变量

[`arrayList.hpp`](./arrayList.hpp) 保存：

```text
element      指向容量为 arrayLength 的数组
listSize    当前逻辑元素数
arrayLength 当前容量
```

必须始终满足：

```text
element != nullptr
1 <= arrayLength
0 <= listSize <= arrayLength
有效逻辑元素恰在 element[0..listSize)
```

示例：

```text
下标       0     1     2     3     4     5
存储      [10]  [20]  [30]  [?]   [?]   [?]
           └────有效区────┘  └──备用容量──┘
listSize = 3, arrayLength = 6
```

`size` 是抽象表长度，`capacity` 是当前分配策略的实现细节。两个列表可以包含相同元素，却有不同容量。

## 4. 随机访问与顺序查找

连续存储通过 `element+i` 直接定位第 `i` 个槽位，因此合法下标访问为 `Theta(1)`。访问前仍需检查负数与 `i>=listSize`，非法时抛 `std::out_of_range`。

`indexOf(x)` 不知道值的位置，只能从头比较：

- 首项命中最好 `Theta(1)`；
- 不存在或只在末尾最坏 `Theta(n)`；
- 额外空间 `Theta(1)`。

重复值返回第一项。若需要按键快速查找，应选择第 10 章字典或第 14–15 章搜索树；不能因为底层是数组就自动获得二分查找，二分要求按键有序，而线性表只维护位置顺序。

## 5. 插入：先保存实参，再从右向左移动

在 `[10,20,30]` 的位置 1 插入 `15`：

```text
原来： [10,20,30,_]
移 30： [10,20,30,30]
移 20： [10,20,20,30]
写 15： [10,15,20,30]
```

移动必须从右向左，否则先写 `a[2]=a[1]` 后再写 `a[3]=a[2]` 会复制已经覆盖的新值。

本章还有一个容易忽略的别名问题：

```cpp
list.insert(0, list.at(2));
```

参数引用指向列表内部。若函数先扩容或移动，引用可能失效或所指值被覆盖。因此两个实现都先复制 `theElement` 到局部 `value`，再改变容器。

有足够容量时，尾部插入移动 0 项，是 `Theta(1)`；头部插入移动 `n` 项，是 `Theta(n)`；任意位置最坏 `Theta(n)`。

## 6. 扩容：一次昂贵，序列均摊便宜

当 `listSize==arrayLength`，`arrayList` 将容量翻倍：

1. 检查 `2*capacity` 不会超出 `int` 范围。
2. 分配新数组。
3. 把插入点前元素复制到原位置。
4. 写入新值。
5. 把插入点后元素复制到右移一格的位置。
6. 所有复制成功后释放旧数组并提交新指针。

使用临时 `unique_ptr<T[]>` 持有新数组。如果复制抛异常，临时数组自动释放，旧列表仍保持原值；这是强异常保证的基本做法。

一次扩容需 `Theta(n)` 移动。若只做尾插并按 1、2、4、8 倍增，直到插入 `n` 项的总搬移量：

```text
1 + 2 + 4 + ... < 2n
```

所以一串尾插每次的均摊成本为 `O(1)`。这不表示每次都常数；触发扩容的那一次仍是线性时间。中间插入即使不扩容也要移动后缀，不能获得常数均摊。

## 7. 删除：从左向右填补空位

从 `[10,20,30,40]` 删除位置 1：

```text
删 20：逻辑空位在 1
移 30： [10,30,30,40]
移 40： [10,30,40,40]
size--：有效区变为 [10,30,40]
```

移动方向从左向右。尾删 `Theta(1)`，头删最坏 `Theta(n)`。本实现不会因删除而自动缩容，所以删除不使已取得的底层分配立刻变小。

`arrayList` 用 `new T[capacity]`，分配时所有槽位已经构造。删除后只减小逻辑长度，不能手动对某个槽位调用析构函数再让最终 `delete[]` 析构一次，否则会双重析构。这个选择也导致它要求 `T` 可默认构造。

## 8. 两种实现为什么类型要求不同

| 方面 | `arrayList<T>` | `vectorList<T>` |
| --- | --- | --- |
| 存储管理 | 手写 `new T[] / delete[]` | `std::vector<T>` |
| 备用槽位 | 预先构造为 `T` | 只有实际元素被构造 |
| 类型要求 | 默认构造、复制／赋值；查找需相等比较 | 不要求默认构造；具体操作需构造／移动／比较 |
| 扩容 | 手动倍增与复制 | 交给标准容器 |
| 元素生命期 | 容量内槽位全部存活 | `[0,size)` 元素存活 |

[`testArrayLists.cpp`](./testArrayLists.cpp) 用 `NoDefault` 类型验证 `vectorList` 能保存不可默认构造对象；同一测试不会用于 `arrayList<NoDefault>`，因为后者的存储策略本身要求默认构造。

这不是模板“支持所有类型”的失败，而是实现选择形成的清晰约束。若要让手写列表支持不可默认构造类型，需要分离原始存储与对象构造，使用 placement new、显式析构和分配器；这已超出本章重点。

## 9. 复制、赋值与所有权

`arrayList` 独占动态数组，因此需要处理资源管理：

- 复制构造分配独立数组并复制有效元素；
- 析构释放数组；
- 赋值使用“复制后交换”，自然处理自赋值并保持异常安全；
- `swap` 只交换三个状态字段。

若只复制 `element` 指针，会发生浅复制：两个对象共同释放同一数组，并且修改一个会污染另一个。测试先复制列表，再改副本，确认原列表不变。

`vectorList` 的 `std::vector` 已提供正确值语义，因此默认生成的复制和赋值即可完成深复制。优先使用标准容器能减少资源管理错误，但手写实现帮助理解其内部约束。

## 10. 迭代器与失效规则

`arrayList` 的迭代器本质上包装指针，`begin()` 指向首元素，`end()` 指向有效区末端；空表时二者相等。连续随机访问迭代器允许 `std::sort(list.begin(),list.end())`。

以下操作会使已有迭代器或引用失效：

- 扩容：旧数组整体释放，所有指针、引用、迭代器失效。
- 在中间插入或删除：操作位置及其后的元素被移动，其身份与位置关系改变。
- 容器销毁：全部失效。

即使没有扩容，插入位置之前的指针在本实现中地址仍可能不变，也不应跨越复杂修改长期保存非拥有引用。讲义中的安全规则是：修改结构后重新获取迭代器。

## 11. 接口中的教学遗留：`get` 的 const 正确性

[`linearList.hpp`](./linearList.hpp) 保留教材接口 `T& get(int) const`。它允许通过 `const linearList<T>&` 获得可写引用，破坏 C++ 的 const 语义。两个实现为了兼容该抽象接口必须保留它；新代码应优先用：

```cpp
T& at(int i);
const T& at(int i) const;
```

这是一个重要设计教训：抽象基类的签名会约束所有实现，错误的 const 设计很难在派生类单独修好。后续扩展接口时应在 ADT 层先审查可变性。

## 12. 复杂度总表

设 `n=size`，元素复制、移动、比较视为 `O(1)`：

| 操作 | 最好 | 最坏 | 说明 |
| --- | ---: | ---: | --- |
| `empty/size/capacity` | `Theta(1)` | `Theta(1)` | 读字段 |
| `at/get` | `Theta(1)` | `Theta(1)` | 边界检查 + 下标 |
| `indexOf` | `Theta(1)` | `Theta(n)` | 顺序查找 |
| 尾部插入 | `Theta(1)` | `Theta(n)` | 扩容时线性；倍增下均摊 `O(1)` |
| 位置插入 | `Theta(1)` | `Theta(n)` | 移动后缀 |
| 尾部删除 | `Theta(1)` | `Theta(1)` | 只减长度／标准容器销毁末项 |
| 位置删除 | `Theta(1)` | `Theta(n)` | 移动后缀 |
| 复制整个表 | `Theta(n)` | `Theta(n)` | 深复制 |

连续数组存储为 `Theta(capacity)`；若只按逻辑元素数报告，应注明备用容量可能不到两倍（倍增策略稳定后）。

## 13. 测试怎样验证数据结构

[`testArrayLists.cpp`](./testArrayLists.cpp) 不只验证一个快乐路径：

- 空表、头中尾插入、重复值查找、头尾删除；
- 负下标、越界访问和非法插入抛异常；
- 从自身元素插入，分别覆盖扩容与不扩容情形；
- 复制、赋值、自赋值与副本独立性；
- 迭代器交给 `std::sort`；
- 3000 步随机操作与 `std::vector<int>` 逐步对照；
- `vectorList<NoDefault>` 的类型能力。

随机对照能发现很多状态错误，但仍不能代替表示不变量和移动方向的证明。测试与证明分别回答“这些案例是否工作”和“所有满足前置条件的输入为何工作”。
