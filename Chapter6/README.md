# 第 6 章：链式线性表与四个应用

本章继续使用第 5 章的线性表 ADT，但将元素放在独立的**结点**中，用链接决定先后顺序。阅读顺序：先理解结点与三种链表，再看稳定分桶如何支撑箱子排序和基数排序，最后看双链表用于凸包、父链接用于并查集。配套的 `chapter6Demo.cpp` 展示运行结果，`testChapter6.cpp` 检查边界与正确性。

## 1. 抽象线性表与链式描述

线性表仍是有位置顺序的序列 `(a₀, a₁, …, aₙ₋₁)`。`linearList.hpp` 规定 `get`、`indexOf`、`insert`、`erase` 等操作；数组表与链表实现的是**同一组行为**，区别在于如何保存元素。

数组表把元素连续放在内存中；单链表则让每个结点单独存放一个元素和一个“后继地址”：

```text
firstNode ──► [10 | next] ──► [20 | next] ──► [30 | nullptr]
                  结点 0            结点 1            结点 2
```

`chainNode.hpp` 中的 `chainNode<T>` 包含 `element` 与 `next`。`next == nullptr` 表示走到表尾。`chain.hpp` 还维护 `lastNode` 和 `listSize`：空表时首尾均为空；非空时尾结点的 `next` 为空。`initialCapacity` 参数只是兼容教材的接口，链表不会预留那么多个结点。

**关键区别：** 给出第 `i` 个元素的下标，数组可以算地址直接访问；单链表必须从表头沿 `next` 走 `i` 步。另一方面，已经找到插入位置的前驱结点后，单链表只需改少数链接，无需搬动后面所有元素。

## 2. 单链表如何插入、删除与复制

在 `10 → 30` 中插入 `20`，先找到 `10` 这个前驱，再进行：

```text
fresh->next = previous->next;  // 新结点指向 30
previous->next = fresh;        // 10 改为指向 20
```

必须先接好新结点的后继，否则可能失去访问原后继的路径。删除 `20` 则让 `10` 直接指向 `30`，再释放 `20` 的结点。删除头结点时改变 `firstNode`；删除尾结点时也更新 `lastNode`。

`chain` 的拷贝构造逐个创建新结点，所以副本与原表没有共享结点；赋值采用先复制再交换，支持自赋值。`push_back` 使用尾指针，能常数时间尾插。`get(i)` 沿用教材 ADT 的签名；若需要 const 正确的读取，可使用 `at(i)` 的 const 重载。

| 操作 | 单链表 | 数组表（第 5 章） |
| --- | --- | --- |
| 读第 `i` 个元素 | `O(i+1)`，最坏 `O(n)` | `O(1)` |
| 按值找首次位置 | 最坏 `O(n)` | 最坏 `O(n)` |
| 头插／删头 | `O(1)` | 最坏 `O(n)` |
| 尾插 | 维护尾指针，`O(1)` | 均摊 `O(1)`，扩容一次最坏 `O(n)` |
| 删尾 | 需找前驱，`O(n)` | `O(1)` |
| 已知前驱后的插入／删除 | 链接操作 `O(1)` | 后缀移动 `O(n)` |
| 额外存储 | 每个结点有指针 | 可能有未使用的容量 |

表中的“已知前驱”不包括**寻找前驱**的时间。`insert(i, x)` 若只知道下标，一般仍需从头走到位置 `i-1`，最坏 `O(n)`。链式存储改善的是局部改链接的成本，不是随机下标访问。

`iterator.hpp` 给单链表提供前向迭代器：`begin()` 从首结点开始，反复 `++` 顺着链接走，`end()` 对应空指针。它支持范围 `for`，但不能像数组指针那样做 `begin() + i`。删除结点会使指向该结点的迭代器失效；插入或重排结点后，应重新确认原迭代器所代表的位置。

## 3. 循环单链表与头结点

`circularList.hpp` 使用一个**不计入数据元素数**的头结点 `headerNode`。尾结点指回头结点，形成环：

```text
header ──► [10] ──► [20] ──► header
   ▲                              │
   └──────────────────────────────┘
```

空表时 `header->next == header` 且 `tail == header`。有了头结点，首元素前也有一个固定的前驱，插入和删除的链接操作更统一；循环条件是“走回头结点”，不能再用 `nullptr` 判断结束。实现还维护尾指针，使 `push_back` 为 `O(1)`。但单向链接仍无法直接从尾找到前驱，所以删尾最坏 `O(n)`。

`extendedLinearList.hpp` 在基本 ADT 上增加 `clear()` 与 `push_back()`；它必须**公开继承** `linearList`，才能通过扩展接口使用基本线性表操作。原实现的 `indexOf` 会在 const 查询中改写头结点的 `element` 当哨兵；新版直接遍历有效结点，不修改表的内容。由于头结点本身带一个 `T element`，这种教学实现要求 `T` 可以默认构造。

## 4. 双向链表：为什么多一条 `prev`？

`doublyLinkedList.hpp` 的每个结点同时有 `prev` 和 `next`。它也使用循环头结点：`header->next` 指头，`header->prev` 指尾；空表时两者都回到 `header`。

```text
header ⇄ [10] ⇄ [20] ⇄ [30] ⇄ header
```

删除已找到的结点 `p` 时，只需让 `p->prev->next = p->next`、`p->next->prev = p->prev`，然后释放 `p`。因此删尾 `pop_back()`、取尾 `back()`、取倒数第二个元素 `secondBack()` 都是 `O(1)`。按下标找中间结点依旧需要走链接；实现会从离下标较近的一端出发，但最坏仍为 `O(n)`。代价是每个数据结点比单链表多保存一个指针，修改链接时也必须同时维护两个方向。

循环头结点让空表和非空表都满足同一链接不变量，这也使复制、清空和尾插的边界情况较容易检查。它同样要求 `T` 可默认构造，以创建头结点。

## 5. 应用一：箱子排序（bucket / bin sort）

假设学生分数是 `0..range` 的整数。为每个分数建一个“箱子”，按原顺序把记录放进对应箱子，最后从低分箱到高分箱收集。例如：

```text
原表：(2,A) (1,B) (2,C) (0,D)
箱 0：(0,D)      箱 1：(1,B)      箱 2：(2,A) (2,C)
结果：(0,D) (1,B) (2,A) (2,C)
```

同分的 A、C 保持先后顺序，这叫**稳定**。`chain::stableBucketSort` 先检查所有桶号，再把原结点从旧链上摘下，分别接到每个箱子的尾部，最后按桶号重接成一条链。它没有为每个记录重新分配结点；先检查桶号也避免遇到非法分数时把原链拆到一半。`chain::binSort` 和 `binSort.cpp` 中的学生记录包装都复用这段逻辑。

若 `n` 是记录数、`k = range + 1` 是箱子数，时间 `O(n+k)`，辅助空间 `O(n+k)`（每个记录的桶号和各桶首尾指针）。这适合键范围不大的情况；若分数范围远大于记录数，建立大量空箱子不划算。它也不同于仅靠比较元素的排序算法。

## 6. 应用二：基数排序（radix sort）

`radixSort.hpp` 实现非负整数的 LSD（least significant digit，最低位优先）排序。以十进制为例，先按个位稳定分桶，再按十位，最后按百位：

```text
170, 45, 75, 90, 802, 24, 2, 66
个位后：170, 90, 802, 2, 24, 45, 75, 66
十位后：802, 2, 24, 45, 66, 170, 75, 90
百位后：2, 24, 45, 66, 75, 90, 170, 802
```

**为什么每趟必须稳定？** 十位相同的两个数已经按个位排好；十位分桶时若颠倒它们，上一趟的成果就被破坏。每趟调用稳定的结点分桶，因此处理完第 `d` 位后，低 `d` 位的整体顺序正确。代码先拒绝负数，支持 `base ≥ 2`，并在扩大位权时避免整数溢出。

若最大数有 `d` 个 `base` 进制位、桶数为 `base`、元素数为 `n`，时间 `O(d(n+base))`，辅助空间 `O(n+base)`。这里的 `d` 不是固定常数时，不应把时间简写成 `O(n)`。

## 7. 应用三：凸包与双链表栈

平面上一组点的凸包，可以想成用橡皮筋包住所有点时橡皮筋经过的最外层顶点。`convexHull.hpp` 使用 Andrew 单调链算法：

1. 将点按 `x`、再按 `y` 排序并去重；这一部分使用 `std::vector`，因为排序需要随机访问。
2. 从左到右建立下链，从右到左建立上链；各用一个双链表当栈。
3. 读入新点 `c` 时，看栈尾两点 `a,b` 与 `c` 的叉积：`cross(a,b,c) > 0` 是左转；`≤ 0` 时弹出 `b`，直到形成正确转向。
4. 去掉上下链重复的端点，连接成逆时针凸包。

例如正方形四角加中心点 `(1,1)`，中心点会在建立链时被弹出，结果只保留四角。共线的中间点也会被弹出；所有点共线时返回两个端点。双链表的 `back()`、`secondBack()`、`pop_back()` 均为 `O(1)`，所以建上下链本身为 `O(n)`；排序主导总时间 `O(n log n)`，空间 `O(n)`。

代码以 `long long` 计算叉积，并限制每个坐标绝对值不超过 `10^9`，以避免该计算溢出。输入与输出是 `chain<Point>`；中间使用数组排序和双链表栈，展示数据结构可以各司其职。

## 8. 应用四：并查集（不相交集合）

并查集管理若干互不重叠的集合，常用于动态连通性：`unite(a,b)` 合并两个元素所在的集合；`connected(a,b)` 判断它们是否已连通。例如先连接 `0-1`、`1-2`，则 `0` 与 `2` 连通；再连接 `4-5` 不会让 `0` 与 `5` 连通。

`disjointSet.hpp` 将每个集合组织成一棵**父链接树**。`parent[i]` 保存父结点编号，根满足 `parent[root] == root`。`find(i)` 沿父链接走到根；返回时把路径上的结点直接接到根上，叫**路径压缩**。`unite` 总让小树根接到大树根，叫**按大小合并**。

```text
合并前：0 → 1 → 根 2       3 → 根 4
合并后：两棵树的根通过一条父链接接起来
```

实现用 `std::vector<int>` 保存父结点编号和集合大小；逻辑结构是由父链接形成的森林，**不是线性链表**。`find`、`unite`、`connected` 在这两种优化一起使用时，摊还时间为 `O(α(n))`，`α` 是增长极慢的反阿克曼函数；空间 `O(n)`。`unite` 返回 `false` 表示两个元素本就在同一集合，集合数不会再减少。编号必须位于 `[0,n)`。

## 9. 原代码中的问题与本章接口约定

原始结点构造没有完整初始化 `next`；原单链表复制遇到异常可能遗留已分配结点；成员箱子排序的 `top` 类型错误；独立箱子排序少处理了一个记录且学生姓名是未明确归属的裸指针；循环表扩展接口是私有继承，并在 const 查找中修改头结点。新版修复这些问题，并补上此前缺少的双链表、基数排序、凸包和并查集。

三个链表的无效下标抛 `std::out_of_range`；单链表构造的 `initialCapacity < 1`、非法桶数或基数等抛 `std::invalid_argument`。教材 ADT 的 `T& get(int) const` 有 const 正确性缺陷，本章为兼容后续章节保留它，并额外提供 const 正确的 `at`。链表的虚函数 `indexOf`、`output` 需要元素支持 `==` 和流输出 `<<`。
