# 第 8 章：栈及其应用

本章从线性表出发，只开放**一端**作为入口和出口，得到栈。先理解栈的“不变量”和两种存储方式，再观察同一个后进先出（LIFO）规则怎样处理括号、汉诺塔与列车重排。后三个应用展示栈在平面配对、图遍历和回溯中的作用。建议阅读顺序：第 1～3 节 → `chapter8Demo.cpp` → 第 4～9 节 → `testChapter8.cpp`。

## 1. 什么是栈？为什么它是线性表？

栈里的元素仍有前后顺序，因此它是**操作受限制的线性表**。普通线性表允许按下标插入或删除；栈只允许在**栈顶** `push`、查看 `top` 和 `pop`。最后放入的元素最先取出，叫 LIFO（last in, first out）。

```text
push(10), push(20), push(30)

栈顶 → [30]
        [20]
栈底 → [10]

top() = 30；pop() 后，top() = 20。
```

`stack.hpp` 是抽象数据类型（ADT）：定义 `empty()`、`size()`、`top()`、`pop()`、`push(value)`，不规定元素在内存中的样子。`top()` 返回引用但**不删除**元素；`pop()` 删除但不返回元素，因此若要保存栈顶，应先复制 `top()` 再 `pop()`。空栈调用二者都会抛 `stackEmpty`。接口还分别提供可写与只读的 `top()`。

**一个常见误解：** 栈能存很多元素，但你不能跳到中间取第 `i` 个。为了访问下面的元素，必须先移走上面的元素。恰恰是这种限制，使它适合“最近尚未完成的任务”或“返回上一层状态”的问题。

## 2. 数组栈与链栈

### `arrayStack`：数组尾部作栈顶

`arraystack.hpp` 使用 `std::vector<T>` 这个连续数组线性表。`push` 等同尾部追加，`pop` 删除尾元素，`top` 读取最后一个元素。容量不足时数组扩容，可能把元素搬到新地址；这一次 `push` 为 `O(n)`，但连续追加的**均摊**时间为 `O(1)`。`top`、`pop` 为 `O(1)`，额外容量可能大于当前大小。数组扩容会使旧引用失效，因此不要跨 `push` 长期保存 `top()` 的引用。

原文件的 `push` 只有声明，`pop` 的空栈判断方向也写反，还在 `new T[]` 的槽位上手动调用析构函数。新版让 `std::vector` 管理扩容与元素生命期，并在从本栈元素压入时先复制值。

### `linkedStack`：单链表头作栈顶

`linkedstack.hpp` 借用第 6 章的 `chainNode<T>`，让 `topNode` 指向栈顶。压栈创建新头结点，令其 `next` 指向旧头；弹栈把头指针移到下一个结点并释放旧头：

```text
原来：top → [20] → [10] → nullptr
push(30)：top → [30] → [20] → [10] → nullptr
```

`top`、`push`、`pop` 都是 `O(1)`，每个元素要多存一个链接指针，并且每次 `push` 都可能单独分配结点。链栈不发生整体搬移，未删除结点的引用通常保持有效。新版初始化大小、实现深拷贝与赋值，避免两个栈误共享同一条链。构造参数 `initialCapacity` 只为接口对照，链栈不会预分配结点。

| 操作 | 数组栈 | 链栈 |
| --- | --- | --- |
| `top`、`pop` | `O(1)` | `O(1)` |
| `push` | 均摊 `O(1)`，扩容一次 `O(n)` | `O(1)`，含一次结点分配 |
| 空间 | `O(capacity)`，有预留槽位 | `O(n)` 个结点及链接 |
| 适合 | 连续访问、缓存局部性好 | 大小频繁变化、希望旧结点不因扩容搬移 |

二者都实现 `stack<T>`，应用只需要遵守 ADT 的规则，无须知道底层是哪一种。

## 3. 看见“待完成的最近任务”：栈的核心思路

很多应用可用同一个提问方式分析：

1. **什么信息还没完成？** 把它压栈。
2. **下一步需要处理哪一个？** 取最近压入的栈顶。
3. **什么时候完成或放弃？** 完成时弹栈；放弃时弹栈并回到之前状态。

括号匹配的待完成信息是“尚未闭合的左括号”；汉诺塔是“待执行的子问题”；车厢缓冲轨道保存“暂不能输出的车厢”；迷宫栈保存“当前位置以及还没试过的方向”。在写代码前先说清栈里每个元素的含义，可以减少很多边界错误。

## 4. 应用一：括号匹配

`bracket.hpp` 支持 `()`、`[]`、`{}`，忽略其他字符，位置从 0 开始。扫描左括号就把**类型与位置**压栈；遇到右括号时，它只能匹配栈顶，因为里面打开的括号必须先关闭。

```text
表达式：a{b[c](d)}
读到 ] 时，最近尚未关闭的是 [；
读到 ) 时，最近尚未关闭的是 (；
最后 } 关闭最外层的 {。
```

如果栈空，或栈顶类型与当前右括号不符，该右括号记为未匹配，栈顶先保留；后面的字符可能仍能关闭它。例如 `([)]` 中，位置 2 的 `)` 不能越过 `[` 去匹配 `(`，位置 3 的 `]` 与 `[` 匹配，最后 `(` 未闭合。`matchBrackets` 返回匹配位置对、未匹配左括号及未匹配右括号，`printMatchedPairs` 负责输出。每个字符至多进出栈一次，时间 `O(n)`，空间最坏 `O(n)`。

## 5. 应用二：汉诺塔

规则：每次只移动一片盘，任何时候大盘不能放在小盘上。要把 `n` 片盘从柱 1 移到柱 3，借柱 2 中转：

1. 先把上面 `n-1` 片从 1 移到 2。
2. 把最大的盘从 1 移到 3。
3. 再把 `n-1` 片从 2 移到 3。

这就是递归式 `M(n)=2M(n-1)+1`、`M(0)=0`，所以最少移动 `2^n-1` 次。`hanoi.hpp` 没有使用全局塔数组：它用**任务栈**显式保存 `(盘数,来源,目标,辅助柱)`，并用三个数组栈模拟真实盘子。因为任务栈后进先出，代码把“后半个子问题、移动最大盘、前半个子问题”按逆序压入，弹出时执行顺序才正确。每次真实搬移还检查源柱非空、目标柱的顶盘比当前盘大。

`solveHanoi(n)` 返回全部移动，时间与输出数量均为 `Θ(2^n)`；显式任务栈深度是 `O(n)`，但返回的移动列表需要 `Θ(2^n)` 空间。因此演示限制 `0≤n≤20`，避免一次性产生极多移动。若只逐步打印而不保存列表，可降低结果存储需求，却不能减少移动次数。

## 6. 重点应用：列车车厢重排

输入轨道依次送来编号 `1..n` 的一个排列，目标输出轨道必须得到 `1,2,…,n`。中间有 `k` 条缓冲轨道，**每条只能从同一端进出**，所以它是栈。`railroad.hpp` 的 `rearrangeRailroad(input,k)` 返回是否成功及完整搬移记录，不使用全局变量。

### 先建立缓冲轨道的不变量

若车厢 `3` 压在栈底、`2` 压在上面，可以先输出 `2` 再输出 `3`；若 `3` 压在 `2` 上面，`2` 会被挡住。因此一条缓冲轨道从**栈底到栈顶必须严格递减**，只有当前车厢 `c < top` 才能压到非空轨道。

对输入 `[3,4,2,1]`，使用两条轨道时：

| 下一辆输入 | 操作后轨道 1（底→顶） | 轨道 2（底→顶） | 已输出 |
| --- | --- | --- | --- |
| 3 | `[3]` | `[]` | `[]` |
| 4 | `[3]` | `[4]` | `[]` |
| 2 | `[3,2]` | `[4]` | `[]` |
| 1 | `[3,2]` | `[4]` | `[1]` |
| 冲刷栈顶 | `[]` | `[]` | `[1,2,3,4]` |

这里只有一条缓冲轨道时，先放 `3` 后遇到 `4`：`4` 不能压在 `3` 上，也不能直接输出（还等 `1`），所以失败。**轨道里有目标车厢也不够；它必须已经在栈顶才能出轨。**

### 贪心选择与完整流程

维护 `nextNeeded`（下一个必须输出的编号）。若当前输入车厢等于它，就直接输出，并反复检查是否有缓冲轨道栈顶恰好是新的 `nextNeeded`，能出则立即输出。否则，为车厢 `c` 选择“栈顶大于 `c` 且栈顶编号最小”的非空轨道；若没有，选第一条空轨道；两者都没有则失败。选最接近的较大栈顶，使编号更大的轨道保留给之后可能到来的中间编号，同时维持每条轨道的递减不变量。

代码先验证输入确实是 `1..n` 的排列，防止重复或缺号误导“下一个编号”。失败结果保留此前的搬移记录和 `nextNeeded`，便于追踪失败点。每辆车厢最多进缓冲一次、出缓冲一次；每次选轨道或寻找可输出栈顶最多扫描 `k` 条轨道，时间 `O(nk)`，空间 `O(n+k)`（包括轨道和搬移记录）。测试还把 `n≤5` 的所有输入排列、`k=0..3` 的结果与穷举所有可用轨道选择的参照算法逐一对照。

## 7. 应用三：开关盒布线

把开关盒的接线端按盒子边界顺序列出，每根线的编号出现两次。若端点排列为 `A B A B`，两根线的端点交替，盒内不交叉连接不可能；`A B B A` 则可以嵌套连接。`switchBox.hpp` 把第一次出现的编号压栈，第二次出现时要求它正好是栈顶。逻辑与括号匹配相同：最近开始、尚未结束的线必须先闭合。

代码要求每个编号恰好出现两次；无效输入抛 `std::invalid_argument`。对 `m` 个端点，平均时间 `O(m)`、空间 `O(m)`（散列表验证次数及栈）；这描述的是平面盒内、端点顺序固定的非交叉配对模型，不能直接推广到允许多层布线的电路板。

## 8. 应用四：离线等价类

等价关系满足自反、对称、传递。给出 `(a,b)` 表示两者等价时，所有能经关系链相连的元素属于同一类。**离线**表示先收到全部关系，再一次性求类别；`offlineEquivalence.hpp` 先建无向图邻接表，再用链栈做迭代深度优先搜索（DFS），每次搜索得到一个连通分量。

例如关系 `(0,1),(1,2),(3,4)`、元素为 `0..5`，结果是 `{0,1,2}`、`{3,4}`、`{5}`。访问标记在压栈时设置，避免同一元素被反复压入。输出中每类元素排序，便于阅读；建图与 DFS 为 `O(n+m)`，排序全部类别额外最坏 `O(n log n)`。若关系需要在线增量合并，第 6 章的并查集更合适；这里用栈展示“一次给定全部关系后遍历”的思路。

## 9. 应用五：迷宫老鼠与回溯

`maze.hpp` 用 0 表示通路、1 表示墙，坐标按 C++ 数组习惯**从 0 开始**。深度优先搜索的栈帧保存 `(行,列,下次要尝试的方向)`。进入未访问过的通路就压栈并把格子加入当前路径；四个方向都不能走时弹栈，从路径删除该格，回到上一个岔路口继续试。

```text
0 0 #       路径：(0,0) → (0,1) → (1,1) → (2,1) → (2,2)
# 0 #
# 0 0
```

栈帧里的“下次方向”很重要：回退时不能从头重复尝试已经失败的方向。`visited` 防止在环中无限兜圈；函数返回**任意一条**可达路径，找不到返回空路径，**不保证最短**（最短路径通常用广度优先搜索）。对 `r×c` 个格子，时间 `O(rc)`，访问标记、栈和路径合计 `O(rc)` 空间。函数验证矩形形状、0/1 格值和起终点范围。
