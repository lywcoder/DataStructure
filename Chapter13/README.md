# 第 13 章：竞赛树（赢者树与输者树）

本章把“反复从几名选手中找出最优者”看成一场淘汰赛。先手算比赛，再认识抽象数据类型（ADT）与类，最后学习两种记录比赛结果的方式及其应用。建议按顺序阅读，并亲手完成末尾练习。

## 1. 从一场比赛开始

有 4 名选手，成绩分别为 `7、2、9、4`。本章约定**数值越小越优先**，所以成绩为 `2` 的选手赢得总冠军。若成绩相同，则**原始下标较小**者获胜。下标从 0 开始；比较的是“`(成绩, 下标)`”，这样每场比赛都有确定结果。

```text
                       总决赛：2 胜 4 → 2
                      /                 \
          半决赛：7 对 2 → 2       半决赛：9 对 4 → 4
                 /       \                /       \
           选手 0(7)  选手 1(2)    选手 2(9)  选手 3(4)
```

最下方的选手是**叶子**；每场比赛对应一个**内部结点**；最上方是**根**。这棵树只记录比较关系，不要求把输入数据排好序。一个选手如果成绩变化，也不必让所有比赛重来：只需重赛从该叶子到根的场次。

人数不一定是 2 的幂。例如 5 名选手可以把比赛位置扩展到 8 个，剩余 3 个位置视为“空位”；遇到空位的选手**轮空晋级**。空位不是成绩为 0 的选手，也不能误选为冠军。

## 2. 抽象数据类型与类：先说能做什么

竞赛树的 ADT 关心使用者能进行哪些操作，不规定用数组还是指针存储。设有 `k` 名选手：

| 操作 | 含义 | 结果或限制 |
| --- | --- | --- |
| `initialize(values)` | 给出全部选手，建立或重新组织比赛 | 复制成绩；允许空输入 |
| `winnerIndex()`、`winner()` | 查看当前冠军 | 分别返回下标、成绩；空树抛 `std::out_of_range` |
| `update(i, value)` | 修改第 `i` 名选手并重赛 | 赢者树可从该叶沿祖先路径更新 |
| `replaceWinner(value)` | 修改当前冠军并重赛 | 输者树的典型操作，用于反复取最优者 |

“类”把这些操作和比赛状态封装在一起。本章的 `winnerTree.hpp`、`loserTree.hpp` 提供以下 C++11 接口；也可直接用成绩数组构造对象：

```cpp
template <class T, class Compare = std::less<T>>
class winnerTree {
public:
    void initialize(const std::vector<T>& values);
    int winnerIndex() const;
    const T& winner() const;
    void update(int index, const T& value);
};

template <class T, class Compare = std::less<T>>
class loserTree {
public:
    void initialize(const std::vector<T>& values);
    int winnerIndex() const;
    const T& winner() const;
    void replaceWinner(const T& value);  // 只替换本轮冠军
};
```

`Compare(a,b)` 为真表示 `a` 更优，默认用 `std::less<T>` 选最小值；相等时仍用选手下标打破平局。两棵树都复制输入成绩，允许重新初始化。空树查询冠军、空输者树替换冠军以及越界更新赢者树均抛 `std::out_of_range`。两种树都能完成选冠军的任务，区别在于内部结点记录谁。

## 3. 赢者树：每场比赛记胜者

沿用开头的四名选手。两个半决赛结点分别记下标 `1`、`3`，总决赛结点记下标 `1`。结点最好存**选手下标**，成绩仍放在叶子对应的数组中；读结点下标后，才能取得该选手当前成绩。根结点保存冠军下标。

```text
叶子下标：       0(7)     1(2)     2(9)     3(4)
半决赛胜者：          1                 3
总决赛胜者：                    1
```

**建树**从叶子向上进行：先比较每对选手，再比较各子比赛的胜者。**更新**时，例如把选手 1 的成绩从 `2` 改为 `10`：

```text
原半决赛：7 对 2  → 选手 1 胜
新半决赛：7 对 10 → 选手 0 胜
新总决赛：7 对 4  → 选手 3 胜
```

选手 2 与 3 的半决赛结果没有变化，无须重算。若更新的是原本落败的选手，也同样从它的叶子开始重赛；该选手可能因此成为新冠军。

## 4. 输者树：每场比赛记败者

输者树进行的是**同一场比赛**，只是每个内部结点记该场败者，总冠军另存于树顶的专用位置。沿用初始成绩：

```text
左半决赛：7 对 2 → 胜者 1，结点记败者 0
右半决赛：9 对 4 → 胜者 3，结点记败者 2
总决赛：  2 对 4 → 胜者 1，结点记败者 3
树顶另存：冠军 1（成绩 2）
```

名字中的“输者”说的是**内部结点存谁**，不是要找最差选手。典型的输者树用于冠军被取走后，由**同一选手位置的新成绩**接替。例如把冠军选手 1 的 `2` 换成 `10`，让新成绩沿原冠军路径向上挑战所记录的败者：

```text
10 对原左半决赛败者 7 → 7 晋级，左结点改记 10
7 对原总决赛败者 4   → 4 晋级，决赛结点改记 7
新冠军是选手 3（成绩 4）；右半决赛结点仍记 9
```

实际实现通常让结点保存下标，以上数字只为便于手算。沿冠军路径重赛之所以够用，是因为各结点保存了当时被冠军淘汰的对手。若要**任意修改一名非冠军选手**，不能直接套用这段冠军替换过程；需要额外保存子树胜者信息，或采用支持任意叶子更新的表示。

| 对比 | 赢者树 | 输者树 |
| --- | --- | --- |
| 内部结点记录 | 每场胜者 | 每场败者 |
| 总冠军位置 | 根结点 | 树顶的独立位置 |
| 本章讲解的快速更新 | 任意选手沿祖先路径重赛 | 替换当前冠军并沿其路径重赛 |
| 常见用途 | 反复查看最优者、更新指定选手 | 反复取冠军并补入新候选者 |

## 5. 数组表示与复杂度

比赛形状固定时，可以使用数组表示：叶子数组保存 `k` 名选手的成绩；内部结点数组保存选手下标。若把叶子位置补齐到 2 的幂，父子位置便能用下标计算。赢者树的结点填入胜者下标；输者树的结点填入败者下标，并另设冠军下标。补出的空位需要单独标记为无效，比较时让真实选手晋级。

令 `k` 为选手数，`k > 0`。补齐后的树高为 `O(log k)`；叶子和内部结点总共占 `O(k)` 空间。

| 操作 | 赢者树 | 输者树（本章的冠军替换方式） |
| --- | --- | --- |
| 建树 | 自底向上 `O(k)` | 暂存子树胜者并自底向上建立败者，`O(k)` |
| 查看冠军 | `O(1)` | `O(1)` |
| 一次更新 | 任意选手 `O(log k)` | 替换冠军 `O(log k)` |
| 存储 | `O(k)` | `O(k)` |

代码使用自底向上建树，所以两种树的初始化都是 `O(k)`。不要把一次重赛的 `O(log k)` 错当成整棵树的建树成本。空树没有冠军；只有一名选手时，冠军就是它本人，不需要进行比较。

## 6. 应用：多路归并

假设有 3 条各自排好序的输入序列：

```text
A: 1, 7
B: 2, 5
C: 3, 6
```

先让每条序列的**当前首元素**参赛：`1、2、3`。冠军 `1` 进入输出后，A 的下一项 `7` 接替 A 原来的参赛位置；重赛后冠军为 `2`。依此进行：

```text
输出 1 → A 补入 7
输出 2 → B 补入 5
输出 3 → C 补入 6
输出 5 → B 已耗尽，退出比赛
输出 6 → C 已耗尽，退出比赛
输出 7 → A 已耗尽
最终输出：1, 2, 3, 5, 6, 7
```

某条序列耗尽时，应把对应参赛位置标记为**无效**，不能补一个可能被误选中的普通数值。若共有 `N` 个元素、`k` 条输入序列，建树后每输出一个元素只需一次沿路径的重赛，总时间为 `O(k + N log k)`（采用线性建树时），竞赛树额外空间为 `O(k)`。外部排序的多路归并会用到这个思路：从多段已排序数据中反复取最小项。

赢者树也可用于“选手成绩不断变化，但始终需要知道当前第一名”的场景。竞赛树与堆都能反复取最优者；竞赛树保留了明确的选手位置和比赛路径，便于更新指定选手或补入某一路的新元素。

## 7. 动手检查是否学会

1. 对成绩 `8、3、3、6` 画出赢者树，标明每场胜者下标及冠军。注意平分时的规则。
2. 在第 1 题的树中，把下标 1 的成绩改为 `9`，只沿必要路径重赛，并写出新冠军。
3. 对开头的 `7、2、9、4`，写出输者树三个内部结点保存的败者下标；再手算冠军 `2` 被 `10` 替换后的两场比赛。
4. 对多路归并例子，说明 B 耗尽时为何不能把它的参赛成绩直接设为 `0`。

**核对答案：** 第 1 题冠军是下标 1（两个 `3` 中下标较小者）；第 2 题冠军变为下标 2；第 3 题初始败者下标依次为 `0、2、3`，替换后冠军为下标 3；第 4 题中 `0` 会被错误选为最小值，必须使用无效位置标记。

## 8. 应用：最先适配与相邻适配装箱

本章另用竞赛树实现**最先适配**（First-Fit）：按输入顺序处理物品，每次找**箱号最小**且剩余容量足够的箱子；如果没有，就开新箱。`firstFitBinPacking` 把每个箱子的剩余容量放在赢者树叶子，比赛选出剩余容量较大的箱子。查找时若某个子树的最大剩余容量仍小于物品大小，就跳过整棵子树；否则优先进入左子树。放入物品后只更新对应叶子到根的比赛。

**相邻适配**按 Next-Fit 解释：仅尝试当前刚打开的箱子；放不下就开新箱，以后不再返回旧箱子。因此它无需竞赛树，一次处理只用常数时间。这两种方法都是按顺序装入的启发式方法，不保证箱子数量全局最少；也不同于第 14 章按“放得下且剩余容量最小”选箱的 Best-Fit。

```cpp
#include "binPacking.hpp"

const PackingResult first = firstFitBinPacking({6, 6, 4, 4}, 10);
// first.binOfItem == {0, 1, 0, 1}
const PackingResult next = nextFitBinPacking({6, 6, 4, 4}, 10);
// next.binOfItem == {0, 1, 1, 2}
```

`PackingResult::binOfItem` 按输入顺序给出箱号，`remaining` 给出各箱剩余容量。箱号从 0 开始。容量必须大于 0，每件物品的大小必须在 `(0, capacity]`，否则抛 `std::invalid_argument`。有 `n` 件物品时，最先适配用 `O(n)` 空间、`O(n log n)` 时间；相邻适配用 `O(n)` 结果空间、`O(n)` 时间。
