# 第 3 章：渐近记法与算法复杂度分析

本章回答两个问题：输入变大时，算法的工作量如何增长？如何从 C++ 代码推导这个增长速度？先读下面的分析，再运行 `complexityDemo.cpp` 对照循环次数；`binary.hpp` 是本章的二分查找实例。

## 1. 先确定分析对象

令 `n` 表示**输入规模**，`T(n)` 表示在约定输入范围内执行的基本操作次数。选择什么作为基本操作要说清楚：查找可计键比较，排序可计比较或移动，遍历可计元素访问。渐近分析关注 `n` 增大时的增长趋势，不直接给出运行秒数。

下文默认一次整数比较、加减、数组按下标访问和固定大小对象的赋值耗时常数；讨论空间时，除非特别说明，只计输入之外的**额外空间**。如果比较对象是长字符串，单次比较可能依赖字符串长度，不能无条件当作常数。输入有多个独立规模时应分别记号，例如矩阵有 `r` 行、`c` 列，完整扫描为 `Θ(rc)`，不能随意把它写成 `Θ(n²)`。

最好、最坏、平均情况描述的是**同一规模下不同输入**的耗时；`O`、`Ω`、`Θ` 描述的是函数增长的界。两组概念应分别使用，例如“二分查找最坏时间为 `Θ(log n)`”。平均时间需要给出输入分布，不能仅凭几个样本推断。

## 2. 大 O、大 Ω、Θ 与严格界

设 `f(n)`、`g(n)` 从某个规模起非负，且 `g(n) > 0`。定义中的常数与起点都**不依赖于 n**。

| 记法 | 含义 | 严格定义 |
| --- | --- | --- |
| `f(n) = O(g(n))` | 渐近上界 | 存在 `c > 0`、`n₀`，对所有 `n ≥ n₀` 有 `f(n) ≤ c g(n)` |
| `f(n) = Ω(g(n))` | 渐近下界 | 存在 `c > 0`、`n₀`，对所有 `n ≥ n₀` 有 `f(n) ≥ c g(n)` |
| `f(n) = Θ(g(n))` | 同阶，既有上界也有下界 | `f(n) = O(g(n))` 且 `f(n) = Ω(g(n))` |
| `f(n) = o(g(n))` | 严格更慢地增长 | `lim(n→∞) f(n)/g(n) = 0` |
| `f(n) = ω(g(n))` | 严格更快地增长 | `lim(n→∞) f(n)/g(n) = ∞` |

例如 `f(n) = n² + 3n + 7`。当 `n ≥ 1` 时，`n² ≤ f(n) ≤ 11n²`，所以 `f(n) = Θ(n²)`。它当然也属于 `O(n³)`，但 `Θ(n³)` 是错的。`n = o(n²)`，而 `n² = ω(n)`。

常见增长顺序（从慢到快）：

```text
1 < log n < n < n log n < n² < n³ < 2ⁿ < n!
```

这里比较的是足够大的 `n`；对数底数只相差常数因子，所以 `log₂ n` 与 `log₁₀ n` 同属 `Θ(log n)`。写有零规模的上界时，可用 `log(n+1)` 避免 `log 0` 未定义。渐近记法隐藏常数和低阶项，不表示较低阶算法在每个小输入上都更快。

## 3. 从循环推导时间

建议按四步分析：**确定规模和计数操作 → 写出执行次数 → 求和或解递推 → 给出界并注明输入条件**。顺序语句的成本相加；条件分支的最坏成本取较贵的可达分支；嵌套循环要算内层在每轮实际运行的次数，不能只看有几层循环。

### 顺序扫描：`Θ(n)`

`complexityDemo.cpp` 的 `linearVisits(n)` 每轮访问一次，共 `n` 次。若循环体只做常数工作，`T(n) = an + b = Θ(n)`。若扫描时一旦找到目标就返回，则最好为 `Θ(1)`，找不到或目标在末尾时为 `Θ(n)`。

### 三角形循环：`Θ(n²)`

`triangularPairs(n)` 的外层 `i` 从 `0` 到 `n-1`，内层在第 `i` 轮运行 `i` 次：

```text
T(n) = 0 + 1 + 2 + ... + (n-1) = n(n-1)/2 = Θ(n²)
```

并非每轮都有 `n` 次内层工作，但总量仍为平方级。这也解释了枚举所有无序元素对为何要做 `n(n-1)/2` 次处理。

### 每次减半：`Θ(log n)`

`halvingSteps(n)` 每轮把正整数 `n` 除以 2，直到不大于 1。对 `n ≥ 1`，循环恰好执行 `⌊log₂ n⌋` 次：

```text
n → ⌊n/2⌋ → ⌊n/4⌋ → ... → 1
```

因此当 `n` 增大时为 `Θ(log n)`。这类循环不能按“有一个 while”就判作线性；关键是剩余问题每轮如何变化。

### 每层做完整扫描：`Θ(n log n)`

`workAtEveryLevel(n)` 有 `⌊log₂ n⌋` 层，每层都完整访问 `n` 个元素，所以计数为 `n⌊log₂ n⌋ = Θ(n log n)`（`n ≥ 2`）。注意内层始终访问原来的 `n` 个元素；若内层只访问不断缩小的 `remaining` 个元素，则总数近似 `n + n/2 + n/4 + ... < 2n`，变为 `Θ(n)`。**同样是“外层减半、内层循环”，还要看内层的边界。**

## 4. 用二分查找分析最好与最坏情况

`binary.hpp` 中的 `binarySearch(a, n, x)` 要求 `n ≥ 0`，`n > 0` 时数组有效且已按非递减顺序排列；未找到返回 `-1`。重复值可能返回任意一个匹配下标。未排序输入不满足算法前提，返回结果没有查找意义。

每轮检查中点 `middle`。若没有找到，只保留左半边或右半边，因此候选区间长度最多约减半。不变式是：**若 `x` 存在，必在当前闭区间 `[left, right]` 中**。例如在 `[0, 2, 4, 6, 8, 10, 12, 14]` 中找 `15`，区间长度按 `8 → 4 → 2 → 1 → 0` 缩小，检查 4 个中点后返回 `-1`。

- 第一次中点就命中：最好时间 `Θ(1)`。
- 没命中时不断减半：最坏需要 `Θ(log n)` 轮；单轮只做常数次比较，故最坏时间 `Θ(log n)`。
- 只保存 `left`、`right`、`middle` 等少量变量：迭代实现的额外空间 `Θ(1)`。
- `n = 0` 时直接返回 `-1`，不访问数组；可以传空指针。

代码用 `left + (right - left) / 2` 计算中点，避免 `(left + right) / 2` 在下标较大时发生有符号整数溢出。这里没有调用排序函数：若先排序再查找，必须把排序成本算进整个流程。

## 5. 递归与空间复杂度

对递归算法，把一次调用拆成“子问题调用 + 本层工作”，写出递推式和终止条件：

| 模式 | 时间递推 | 时间量级 | 常见额外空间 |
| --- | --- | --- | --- |
| 递归二分查找 | `T(n) = T(n/2) + Θ(1)` | `Θ(log n)` | 调用栈 `Θ(log n)` |
| 每层处理 `n` 个元素、产生两个半规模子问题 | `T(n) = 2T(n/2) + Θ(n)` | `Θ(n log n)` | 仅调用栈 `Θ(log n)`；若每层还分配辅助数组，需另算 |

以上均以 `T(1) = Θ(1)` 为基例，并忽略取整对量级的影响。第二行可按递归树理解：每层总工作约 `n`，共有约 `log₂ n` 层。具体算法的空间不能仅由时间递推式推断；例如归并排序常用 `Θ(n)` 辅助数组，此外还有调用栈。

空间分析也要说明是否包括输入与输出：上面的二分查找复用传入数组，额外空间为常数；若函数另外创建长度为 `n` 的数组，额外空间就是 `Θ(n)`。递归调用保存局部状态，栈深度也应计入。

## 6. 复杂度分析常见误区

- **把 `O` 当成精确答案。** `Θ(n)` 同时也是 `O(n²)`；若能证明同阶，优先写 `Θ`。
- **把最好情况与上界混为一谈。** “最好 `Θ(1)`”不意味着“最坏 `O(1)`”。要同时说明输入情形和界。
- **只数循环层数。** 内层边界会变化；先写求和式，再化简。
- **漏掉前处理或隐藏成本。** 排序后再二分查找，总时间要包含排序。容器扩容、字符串比较、对象复制也可能不是常数。
- **用秒数证明渐近界。** 实测时间受编译优化、机器、缓存和输入分布影响；计数可以帮助核对推导，数学上的上下界仍需由算法结构说明。实际计时实验可参考第 4 章。

## 7. 编译、运行与自查

在 `Chapter3` 目录下，用 C++11 编译并运行：

```powershell
g++ -std=c++11 -Wall -Wextra -Wpedantic -Werror complexityDemo.cpp -o complexityDemo.exe
.\complexityDemo.exe
```

演示输出中的 `linear`、`pairs`、`halving`、`n*halving` 分别计 `n`、`n(n-1)/2`、`⌊log₂ n⌋`、`n⌊log₂ n⌋` 次循环体执行；最后一行演示 8 个元素的二分查找对不存在值检查 4 个中点。它统计的是指定操作，并不等于精确的 CPU 指令数。程序用断言核对这些计数，编译时不要加 `-DNDEBUG`。

自查两题：

1. `for (int i = 1; i < n; ++i) for (int j = 0; j < i; ++j) ++count;` 的计数是多少？答：`n(n-1)/2 = Θ(n²)`。
2. 二分查找调用 100 次，数组已排好序且每次查找独立，最坏总查找时间是多少？答：`Θ(100 log n)`，因为 100 是固定常数，也可写 `Θ(log n)`；如果次数 `q` 也是输入变量，应写 `Θ(q log n)`。若还需先排序，应再加上排序的成本。
