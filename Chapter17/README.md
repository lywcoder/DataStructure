# 第 17 章：第三部分·算法设计方法（一）——贪婪算法

本章从“怎样证明一个眼前最好的选择也通向全局最优”入手，学习贪婪算法。随后按问题类型讲解六个应用：货箱装载、0/1 背包、拓扑排序、二分覆盖、单源最短路径和最小成本生成树。全部程序兼容 C++11，实现在 [`greedyAlgorithms.hpp`](./greedyAlgorithms.hpp)，可运行示例在 [`chapter17Demo.cpp`](./chapter17Demo.cpp)，断言测试在 [`testChapter17.cpp`](./testChapter17.cpp)。

## 1. 最优化问题与贪婪思想

最优化问题通常由三部分组成：**候选对象**、**可行性约束**和**目标函数**。例如货箱装载的候选对象是每个货箱，约束是总重量不超过船的载重，目标是装入的货箱数量最多。求解时先区分“找到任意可行解”和“找到最优可行解”：能装下并不意味着数量最多。

贪婪算法按某个局部规则，一步一步把候选对象加入当前解；一旦选定，通常不回头。通用框架如下：

```text
解 = 空
只要还有候选对象：
    按贪婪规则找出眼下最好的候选对象
    如果加入后仍满足约束，就接受它
返回解
```

**局部最优不自动等于全局最优。** 要证明算法正确，常用两个角度：

1. **贪婪选择性质**：存在一个最优解包含当前选择。常用交换论证：把某个最优解的第一步换成贪婪选项，目标值不会变差。
2. **最优子结构**：做完这一步，余下的问题仍可按同样方式求最优。若第一步使未来的可行性或代价发生复杂变化，贪婪选择可能失效。

代码中有三种不同角色，学习时不要把它们混成一类：货箱装载、非负权最短路径和最小生成树是**有最优性保证的贪婪算法**；拓扑排序是**逐步构造可行顺序**，无须优化目标；0/1 背包和本章定义的二分覆盖使用贪婪**启发式**时通常不能保证最优，其中背包还给出动态规划的精确解。

| 应用 | 问题类型 | 每步选择 | 结果保证 | 主要复杂度 |
| --- | --- | --- | --- | --- |
| 货箱装载 | 最大化数量 | 当前最轻的货箱 | 最优 | `O(n log n)` |
| 0/1 背包 | 最大化总价值 | 单位重量价值最高的物品 | 仅启发式；DP 可求最优 | 贪婪 `O(n log n)`；DP `O(nC)` |
| 拓扑排序 | 求可行顺序 | 当前入度为 0 的顶点 | 有向无环图上得到合法顺序 | `O(E + V log V)` |
| 二分覆盖 | 最小化所选左侧顶点数 | 新覆盖右侧点最多的顶点 | 近似解；不保证最少 | `O(E log E + L E)` |
| 单源最短路径 | 最小化各点距离 | 当前暂定距离最小的点 | 非负权时最优 | `O((V+E) log(V+E))` |
| 最小成本生成树 | 最小化树边总成本 | 不成环的最便宜边 | 连通无向图上最优 | `O(E log E)` |

这里 `n` 是货箱或物品数，`C` 是背包容量，`L` 是二部图左侧顶点数，`V`、`E` 是图的顶点数和边数。表中省略常数和较小的辅助项，后文逐一解释。

## 2. 货箱装载：以数量为目标的贪婪选择

**背景。** 一艘船的载重为 `C`，有 `n` 个不可拆分的货箱，重量分别为 `w[i] > 0`。希望装入**最多件**，不是让船的剩余载重最小。函数 [`loadContainers`](./greedyAlgorithms.hpp) 返回选中货箱的原始下标，按选取顺序排列；同重时优先选原始下标较小者。

**算法。** 按重量从轻到重排序，依次装入能放下的货箱。若当前最轻的未选货箱都放不下，后面更重的也放不下，可以停止。

例如容量 `7`、重量 `[4,8,1,3,2]`，排序后为 `1(下标2)、2(下标4)、3(下标3)、4(下标0)、8(下标1)`。前三个总重 `6`，返回 `[2,4,3]`，共 `3` 件。

**为何最优。** 假设某个最优解选了 `k` 件，它们的总重量至少等于全体货箱中最轻 `k` 件的重量之和。所以只要有一种 `k` 件的装法，最轻 `k` 件也必然装得下。贪婪算法能装入的件数因此不会少于任何其他解。

```cpp
std::vector<int> chosen = loadContainers({4, 8, 1, 3, 2}, 7);
// chosen == {2, 4, 3}；对应重量 1、2、3
```

排序花 `O(n log n)` 时间；结果和排序数组用 `O(n)` 空间。容量为 `0`、输入为空时返回空结果；负容量或非正重量抛出 `std::invalid_argument`。

## 3. 0/1 背包：贪婪为什么会失败

**背景。** 第 `i` 件物品有正重量 `w[i]` 和非负价值 `v[i]`，容量为 `C`。每件物品**只能选 0 次或 1 次，不能切开**。目标是在总重量不超过 `C` 的条件下，让总价值最大。

看似合理的贪婪规则是按 `v[i]/w[i]` 从高到低选。实现 [`greedyKnapsack`](./greedyAlgorithms.hpp) 用交叉相乘比较比值，避免浮点误差。但它是启发式：

| 物品 | 重量 | 价值 | 单位重量价值 |
| --- | ---: | ---: | ---: |
| A | 10 | 60 | 6 |
| B | 20 | 100 | 5 |
| C | 30 | 120 | 4 |

容量 `50` 时，贪婪先选 A、再选 B，价值 `160`；之后 C 放不下。最优解是 B+C，价值 `220`。先取 A 占用了容量，却不能把 A 的一部分退回，这一步无法交换为最优解的第一步。**可切分背包**可以按价值密度贪婪地取满最后一件；**0/1 背包**不可以。

要得到精确答案，使用动态规划 [`optimalKnapsack`](./greedyAlgorithms.hpp)。令 `dp[i][c]` 表示只考虑前 `i` 件、容量为 `c` 时的最大价值：

```text
不选第 i 件：dp[i-1][c]
选第 i 件（若 w[i] <= c）：dp[i-1][c-w[i]] + v[i]
dp[i][c] = 两者的较大值
```

计算完表格，从 `dp[n][C]` 逆推：若 `dp[i][c]` 比 `dp[i-1][c]` 大，说明选了第 `i` 件，随后令 `c -= w[i]`；价值相等时约定不选。返回的 `knapsackResult` 含原始下标、总重量和总价值。

```cpp
std::vector<knapsackItem> items{{10, 60}, {20, 100}, {30, 120}};
knapsackResult quick = greedyKnapsack(items, 50);   // 160，启发式
knapsackResult exact = optimalKnapsack(items, 50); // 220，下标 {1, 2}
```

贪婪排序为 `O(n log n)` 时间、`O(n)` 空间；动态规划为 `O(nC)` 时间和空间，其中 `C` 是**整数容量的数值**，因此是伪多项式算法。容量非常大时，二维表可能占用过多内存。负容量、非正重量或负价值抛出 `std::invalid_argument`。

## 4. 拓扑排序：逐步选择当前可执行的任务

**背景。** 有向边 `u→v` 表示任务 `u` 必须在任务 `v` 之前完成。拓扑序要求每条边的起点都排在终点前，只有**有向无环图（DAG）**才有拓扑序。它是约束满足问题，不是“最短”或“最便宜”的最优化问题。

**算法（Kahn）。** 先计算每个顶点的入度。入度为 `0` 的顶点没有未完成前置任务，可立即输出；输出它后，将其每条出边终点的入度减 `1`。反复执行，直到没有可取顶点。代码用小根堆在多个可选顶点中取编号最小者，使示例输出稳定，但其他选择也能产生合法拓扑序。

```text
边：0→2、1→2、2→3；顶点 4 独立
最初可选：0、1、4
结果：0、1、2、3、4
```

循环中不变量是：输出序列中的任务均已满足前置依赖。若结束时输出数量小于顶点数，剩余部分含有有向环，函数 [`topologicalSort`](./greedyAlgorithms.hpp) 抛出 `std::invalid_argument`。顶点编号从 `0` 到 `V-1`；非法编号抛出 `std::out_of_range`。扫描边为 `O(E)`，小根堆每个顶点最多入堆一次，总时间 `O(E+V log V)`，空间 `O(V+E)`。

## 5. 二分覆盖：局部覆盖最多不一定全局最少

**本章定义。** 二部图的左侧顶点代表可选的集合，右侧顶点代表待覆盖对象。边 `L_i—R_j` 表示选 `L_i` 可以覆盖 `R_j`。目标是选**尽量少的左侧顶点**，覆盖**全部右侧顶点**。这个问题等价于集合覆盖，可用贪婪法求近似解，通常不能保证最少。它与“从左右两侧都可以选点、让每条边至少有一个端点被选”的**二部图最小顶点覆盖**不是同一问题。

**算法。** 维护 `covered[j]`。每轮计算每个未选左侧顶点能新增覆盖多少个右侧顶点，选择新增数最大的那个（平局选编号小者），直到全部覆盖；若所有候选的新增数都是 `0` 而仍有未覆盖的右侧点，则无可行覆盖。邻接行中的重复编号先去重，以免虚增覆盖数。

```text
L0 -> {R0,R1}，L1 -> {R1,R2}，L2 -> {R2,R3}
第 1 轮：三者各新增 2，选 L0
第 2 轮：L1 新增 1，L2 新增 2，选 L2
得到 {L0,L2}，覆盖 R0..R3
```

**为什么只能称近似。** 当前覆盖最多的集合可能和后续集合重叠很多，导致最后需要更多集合。对一般集合覆盖，贪婪结果有调和数 `H(R)=1+1/2+…+1/R` 的近似保证；它不是精确最优解的证明。

一个具体反例是 `L0={R0,R1,R2,R3}`、`L1={R0,R1,R4}`、`L2={R2,R3,R5}`。贪婪先选覆盖 `4` 个点的 `L0`，随后还需选 `L1`、`L2` 才能覆盖 `R4`、`R5`，共 `3` 个；直接选 `L1+L2` 只需 `2` 个。

```cpp
std::vector<std::vector<int> > neighbors{{0, 1}, {1, 2}, {2, 3}};
bipartiteCoverResult cover = greedyBipartiteCover(4, neighbors);
// cover.leftVertices == {0, 2}，cover.allCovered == true
```

若有 `L` 个左侧点、`R` 个右侧点、`E` 条边，去重排序约 `O(E log E)`；最多选 `L` 轮，每轮扫描所有边，约 `O(LE)` 时间，空间 `O(E+L+R)`。无法覆盖时返回已选的部分结果并将 `allCovered` 设为 `false`；无效右侧编号抛出 `std::out_of_range`。

## 6. 单源最短路径：Dijkstra

**背景。** 给定带权有向图和起点 `s`，求从 `s` 到每个顶点的最小路径权值和。边权**必须非负**；零权边允许。无向图可把每条边输入为两个方向。不可达顶点的距离记为 `LLONG_MAX`，前驱记为 `-1`。

**算法。** `distance[v]` 保存目前找到的最短候选距离。小根堆每次取暂定距离最小的顶点 `u`，尝试通过其出边 `u→v` 更新 `distance[v]`；这个操作称为**松弛**：

```text
若 distance[u] + weight(u,v) < distance[v]：
    distance[v] = distance[u] + weight(u,v)
    parent[v] = u
```

同一顶点可能多次入堆，弹出时若堆项距离不是当前 `distance[u]`，说明它已经过期，直接跳过。非负边权保证：堆中最小的暂定距离一旦被取出，之后绕其他未处理顶点走一圈不可能再变短。这是贪婪选择成立的关键；有负边时不能使用 Dijkstra。

例如 `0→1(8)、0→2(2)、2→1(1)、1→3(3)、2→3(10)`，从 `0` 出发得到距离 `[0,3,2,6]`，到 `3` 的路径是 `0→2→1→3`。函数 [`dijkstra`](./greedyAlgorithms.hpp) 返回距离和前驱，函数 [`restorePath`](./greedyAlgorithms.hpp) 由前驱恢复路径；不可达目标返回空数组。顶点编号无效或出现负权时抛异常。

邻接表占 `O(V+E)` 空间；允许重复堆项的实现最多生成 `O(E)` 个堆项，时间 `O((V+E) log(V+E))`，额外堆空间 `O(E)`。

## 7. 最小成本生成树：Kruskal

**背景。** 要用最低成本连接所有地点。给定**连通无向带权图**，求一棵覆盖所有顶点、无环、恰有 `V-1` 条边且边权之和最小的树。边权可以为负；自环不会被选择。若图不连通，就不存在覆盖全部顶点的生成树。

**算法。** 将边按成本升序排序；依次检查，若边的两端在不同连通分量，就选它并合并两分量，否则跳过。并查集保存当前连通分量，根相同意味着加入该边会形成环。

```text
边：0-1(4)、0-2(2)、1-2(1)、1-3(5)、2-3(8)
按成本检查：选 1-2(1)，选 0-2(2)，跳过 0-1(4)，选 1-3(5)
总成本 1+2+5=8
```

**为何最优。** 对当前任意两个不同连通分量，跨越这道“切割”的最便宜候选边是安全边：若某棵最优树没选它，把它加进去会成环；环中必有另一条跨越切割的边，删掉那条边后仍是树，成本不会增加。这样可逐步构造出最优生成树。

函数 [`kruskal`](./greedyAlgorithms.hpp) 返回所选边和总成本。排序花 `O(E log E)`，并查集用了路径压缩和按秩合并，查找近似常数时间；整体为 `O(E log E)`，空间 `O(V+E)`。本章约定空图和单顶点图的最小生成树为空、总成本为 `0`；非连通图抛出 `std::invalid_argument`。

### 证明自检

遇到新的贪婪规则时，逐项回答：

1. 当前选择是否能与任意最优解的第一步交换而不变差？
2. 做完选择后，剩余问题是否仍是同一类最优子问题？
3. 平局规则是否只影响输出确定性，还是会影响目标值？
4. 输入前提（非负权、可切分、连通等）在哪一步进入证明？
5. 若无法回答，能否用小规模穷举搜索反例？
