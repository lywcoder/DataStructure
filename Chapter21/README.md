# 第 21 章：分支定界法

分支定界法（branch and bound）在一棵解空间树上寻找最优解。它把尚未扩展的部分方案保存为**活结点**，给每个结点计算一个对最终结果的乐观估计，再选择有希望的结点扩展。本章用货箱装载、0/1 背包、最大完备子图、旅行商和电路板排列说明如何设计**状态、界、可行性检查与优先级**。实现见 [`branchAndBound.hpp`](./branchAndBound.hpp)，演示见 [`chapter21Demo.cpp`](./chapter21Demo.cpp)，测试见 [`testChapter21.cpp`](./testChapter21.cpp)。

### 学习目标与先修知识

先修第 12 章优先队列、第 20 章回溯和各问题的数学模型。学完后应能：

1. 区分活结点、已扩展结点、可行解和乐观界。
2. 为最大化选择大上界优先，为最小化选择小下界优先。
3. 说明优先级只改变搜索顺序，剪枝条件才决定丢弃分支。
4. 在生成子结点和弹出旧结点时都重新用最新最优值检查界。
5. 比较最佳优先法与深度优先回溯的时间、状态复制和峰值空间。
6. 用两船装载证明“先让第一船尽量重”与第二船可行性的等价关系。

## 1. 算法思想：分支、定界与活结点

把一个最优化问题拆成一系列选择。根结点是空方案，树的边是一次选择，内部结点是部分方案，叶结点是完整方案。例如选或不选每件货物得到**子集树**；逐个确定城市访问顺序得到**排列树**。

“分支”是生成子结点；“定界”是估计从一个部分方案出发，最理想情况下能达到什么成绩。始终保存已知的**可行解**（当前最优解，也称 incumbent）：

| 目标 | 结点的乐观界 | 安全的剪枝条件 |
| --- | --- | --- |
| 最大化 | 该分支可能取得的**上界** `upper` | `upper <= best` |
| 最小化 | 该分支不可能低于的**下界** `lower` | `lower >= best` |

上界可以高估，下界可以低估；反过来就可能误删真正的最优解。若界值等于当前最优值，分支最多产生另一个并列最优解，本章只需要返回**一组**最优方案，因此可以剪掉。剪枝只能拿界与**已经找到的可行解**比较，不能把一个估计值当成真实解。

本章选择**最佳优先（best-first）分支定界**：用 `std::priority_queue` 保存活结点，最大化问题先弹出上界最大的结点，最小化问题先弹出下界最小的结点。队列的优先级是“先搜谁”，界与当前最优值的比较才是“能否丢弃谁”。通用流程是：

```text
best = 一个已知可行解，或“尚未找到”
把根结点连同乐观界放入优先队列
while 队列非空:
    取出最有希望的活结点
    if 已有可行解且该结点的界不能改进 best: continue
    for 每个下一步选择:
        if 选择不合法: continue
        生成子结点并计算界
        if 子结点已构成可行答案: 尝试更新 best
        if 子结点还有未决定的选择且界仍可能改进 best: 入队
return best
```

优先队列不保证多项式时间。界越紧，通常能剪掉越多结点；最坏情况下仍可能遍历整棵树。与 [第 20 章的深度优先回溯](../Chapter20/README.md) 相比，本章的关键差异是**保留多个活结点，并按界决定扩展顺序**。回溯沿一条路径深入，通常只需线性级搜索辅助空间；最佳优先法的队列最坏可能占指数级或阶乘级空间。两种方法都可以使用相同的安全界。

下文物品、货箱、顶点、城市、板和网组都从 `0` 编号。输入规模应保持在教学示例范围；这些都是精确求解算法。

## 2. 货箱装载：在容量内尽量装满

### 问题与状态

一艘船容量为 `C >= 0`，货箱 `i` 的重量 `w[i] > 0`。每个货箱只能装或不装，要求总重量不超过 `C`，并使**装载重量最大**。这与背包问题不同：这里没有独立的价值，目标就是重量。教材常见的完整问题还有第二艘船：必须把所有货箱装上，容量分别为 `C1`、`C2`。先最大化第一艘船的装载重量，再判断剩余总重量是否 `<= C2`。因为第一艘装得越重，留给第二艘的重量越小，所以这个判断是充分且必要的。

第 `i` 层决定货箱 `i` 是否装入。结点保存 `(next, weight, selected)`：下一个待决货箱、当前重量、已选下标。装入分支仅在 `weight + w[i] <= C` 时可行；不装入始终可行。任何部分装载都是可行解，因此发现更大重量时可**立即**更新当前最优值，无须等到叶子。

### 界与搜索过程

预处理 `suffix[i] = w[i] + ... + w[n-1]`。即使剩余货箱全部能装入，最终重量也不会超过 `weight + suffix[next]`，同时不能超过船的容量。所以

```text
upper = min(C, weight + suffix[next])
```

这是安全上界，但可能不可达到。例如剩余货箱只有重量 `40`，船还空出 `30`，上界仍可能写成 `C`；乐观不会影响正确性，只会让剪枝变少。样例 `w = [10, 40, 40]`、`C1 = 50`、`C2 = 40`，第一艘选 `{0,1}` 或 `{0,2}` 装 `50`，第二艘装剩下的 `40`。接口 `loadContainers(weights, capacity)` 返回单船最大装载重量和货箱下标；`loadTwoShips(weights, firstCapacity, secondCapacity)` 在此基础上返回是否可行，以及两艘船各自的重量与货箱下标。不可行时 `feasible` 为 `false`，两个下标数组为空。

最坏有 `O(2^n)` 个结点。每个结点复制所选下标最多 `O(n)`，时间 `O(n2^n)`；队列最多存储指数个、每个最多 `O(n)` 大小的结点，空间 `O(n2^n)`。后缀数组另占 `O(n)`。

## 3. 0/1 背包：最大化价值

### 问题与状态

物品 `i` 有正重量 `w[i]` 和非负价值 `v[i]`，容量为 `C`。每件物品至多选一次，要求总重量 `<= C`，总价值最大。结点保存 `(next, weight, value, selected)`；装入分支要先通过容量检查。不装入分支不改变重量和价值。已经选的物品始终是可行背包，因此发现更高价值时也可立即更新答案。

### 价值上界

令 `suffixValue[i]` 为从 `i` 起所有剩余物品的价值之和。忽略这些物品的重量，假设全都能免费放入，得到

```text
upper = value + suffixValue[next]
```

它可能很松，但绝不会低估该分支可能取得的价值。样例 `(重量,价值) = (10,60),(20,100),(30,120)`，容量 `50`。选物品 `{1,2}`，总重量 `50`，最大价值 `220`。根结点的上界是 `280`；当已找到价值 `220` 的方案后，凡上界不超过 `220` 的活结点均可舍弃。接口 `knapsack01(items, capacity)` 返回最大价值、总重量和物品下标。价值相同的方案只保留先找到的一组。

搜索树有 `O(2^n)` 个结点；由于复制部分方案，最坏时间与队列空间均为 `O(n2^n)`。更紧的分数背包上界可以减少实际搜索量，但需要排序、处理单位价值和恢复原下标；本章保留易于证明正确性的后缀价值上界。

## 4. 最大完备子图：找最大团

### 问题与可行性

无向图中，若顶点集合内任意两个不同顶点之间都有边，它就是**完备子图**，也称**团**（clique）。最大团要求顶点数在全图中最多；“极大团”只表示当前集合再也加不进顶点，两者不等价。

输入 `adjacent[u][v]` 是对称的 `0/1` 邻接矩阵，对角线为 `0`。第 `i` 层决定是否选择顶点 `i`。结点中的 `selected` 始终保持两两相邻：只有 `i` 与其中**每一个**顶点都有边，才能生成“选 `i`”子结点。部分团本身就是可行解，可立即更新最大团。

### 顶点数上界

已选 `k` 个，尚有 `n-next` 个顶点未决定。即使全部都能加入，最多也只有

```text
upper = k + (n - next)
```

个顶点。示例图的边为 `(0,1),(0,2),(1,2),(2,3)`；`{0,1,2}` 是大小为 `3` 的最大团。接口 `maximumClique(adjacent)` 返回大小和顶点下标。空图返回空团。

最坏结点数 `O(2^n)`；检查新顶点与已选顶点的相邻性，以及复制部分团，各需 `O(n)`，故时间 `O(n2^n)`。邻接矩阵占 `O(n²)`，活结点队列最坏占 `O(n2^n)`。

## 5. 旅行商问题：最短哈密顿回路

### 问题与排列树

从城市 `0` 出发，访问每座城市**恰好一次**，最后返回 `0`，使费用最小。费用矩阵允许有向边：`cost[u][v] >= 0` 表示边的费用，`-1` 表示无边，对角线必须为 `0`。固定起点 `0` 可避免仅因回路起点不同而重复搜索。结点保存 `(path, used, costSoFar)`；每层追加一个未访问且有边可达的城市。只有所有城市都访问完并且**最后一城到 0 也有边**，才得到可行回路。

### 必需出边下界

对每个城市 `v`，预先计算它在全图中的最小出边费用 `minOut[v]`。已走过的路径边记在 `costSoFar`；路径末端和每个未访问城市将来都必须各有一条出边。因此

```text
lower = costSoFar + minOut[path.back()]
                  + Σ minOut[v]  （v 尚未访问）
```

`minOut[v]` 可能指向已访问城市，甚至几座城市都选同一目的地，故这只是乐观下界；它不会高于任何真实补全回路的费用。若某城市没有出边，且城市总数大于一，则不存在回路。子结点已经访问所有城市时，直接计算返回 `0` 的边，不再使用这个估计。

四城样例矩阵如下，一条最优回路是 `0 -> 1 -> 3 -> 2 -> 0`，费用 `80`：

```text
      0   1   2   3
0     0  10  15  20
1    10   0  35  25
2    15  35   0  30
3    20  25  30   0
```

接口 `travelingSalesperson(cost)` 返回 `minCost` 和包含首尾 `0` 的 `tour`。无回路时返回 `-1` 与空路径；空图也按无回路处理；单城市约定为费用 `0`、路径 `{0,0}`。最坏仍需探索阶乘级路径，复制状态、计算界和堆操作带来 `O(n log n · n!)` 时间；矩阵占 `O(n²)`，活结点最坏占 `O(n n!)` 空间。只接受非负费用，累加超过 `long long` 范围会抛 `std::overflow_error`。

## 6. 电路板排列：最小化最大布线密度

### 目标是什么

若电路板沿背板排成一行，一个**网组**可能连接多块板。某个板间切口左、右两侧都有该网组的引脚时，网组必须跨过切口，占用一条布线通道。切口的**密度**是跨过它的网组数。本题希望让各切口密度中的**最大值尽可能小**，而不是最小化所有切口密度的总和。

输入 `boards[b][net]` 为 `0/1`：板 `b` 是否含网组 `net` 的引脚。`total[net]` 是全体板中含该网组的板数；`placed[net]` 是当前前缀中含该网组的板数。当前前缀后的切口有该网组跨越，当且仅当：

```text
0 < placed[net] < total[net]
```

这一判定支持一个网组连接多块板，不会把同一网组的多个引脚对重复计数。

### 前缀下界

结点保存已排板的 `order`、使用标记 `used`、各网组的 `placed` 和已出现的最大切口密度 `bound`。每层选一块未使用的板追加到前缀，更新 `placed`，数出新切口的 `crossing`，再设

```text
lower = max(原来的 bound, crossing)
```

未来追加板不会改变已经出现的切口，所以这个最大值只会保持或增大，是最终目标的安全下界。只有完成整个排列后，才拿它更新当前最优排列。

例如网组 A 连接板 `{0,2}`，B 连接 `{1,3}`。排列 `0,1,2,3` 的切口密度为 `1,2,1`，目标值为 `2`；排列 `0,2,1,3` 为 `1,0,1`，目标值为 `1`。接口 `arrangeCircuitBoards(boards)` 返回 `minDensity` 和板下标顺序。空输入、无网组或只有一块板的目标值均为 `0`。

有 `n!` 种完整排列；每个生成结点复制最多 `n+m` 的状态、扫描 `m` 个网组并进行堆操作，最坏时间为 `O((n log n + m)n!)`，队列空间为 `O((n+m)n!)`。输入矩阵另占 `O(nm)`。

## 7. 五题的统一视角

| 问题 | 解空间 | 结点优先级 | 乐观界 | 何时获得可行答案 |
| --- | --- | --- | --- | --- |
| 货箱装载 | 选/不选的子集树 | 上界越大越先 | `min(C, 已装重量 + 剩余总重量)` | 每次可行装箱后 |
| 0/1 背包 | 选/不选的子集树 | 上界越大越先 | 当前价值 + 剩余总价值 | 每次可行选物后 |
| 最大完备子图 | 选/不选的子集树 | 上界越大越先 | 已选数 + 未决定顶点数 | 每次得到更大的团后 |
| 旅行商 | 城市排列树 | 下界越小越先 | 当前费用 + 必需最小出边之和 | 找到可返回起点的完整回路后 |
| 电路板排列 | 板排列树 | 下界越小越先 | 已出现的最大切口密度 | 完成全部板的排列后 |

前面三题的部分方案已经满足目标问题的可行性条件，所以可用它们尽早更新最优值，进一步剪枝。后面两题必须先构成完整回路或完整排列。`priority_queue` 中原先入队的结点可能在新最优解出现后失去希望，因此**出队时仍要再检查一次界**。

### 与深度优先回溯逐项比较

| 维度 | 第 20 章回溯 | 本章最佳优先分支定界 |
| --- | --- | --- |
| 活跃状态 | 当前根到结点的一条路径 | 优先队列中的许多部分方案 |
| 下一个结点 | 递归顺序决定 | 界最有希望者 |
| 状态存储 | 原地修改后撤销 | 每个子结点复制自己的向量状态 |
| 搜索辅助空间 | 通常 `O(深度+状态)` | 最坏可存指数／阶乘数量结点 |
| 最坏时间 | 指数或阶乘 | 仍是指数或阶乘，另有复制与堆成本 |
| 首个好解 | 依赖分支顺序 | 好界常帮助较早找到，但不保证总更快 |

两者可以使用同一个安全界。把优先队列换为 FIFO、LIFO 或其他顺序，只要仍完整生成合法分支并执行相同安全剪枝，正确性不变；访问结点数、得到首个可行解的时机和峰值内存可能大幅变化。

### 正确性证明框架

对每个算法应核对：

1. 根表示空方案，每个合法完整方案都能沿唯一或至少一条分支路径生成。
2. 结点状态足以生成所有后继；复制后父结点不会被子结点修改。
3. `bound` 对该结点下的每个完整方案都保持正确方向。
4. `best` 只由真实可行方案更新，不由界值更新。
5. 队列最终为空时，未扩展分支都已证明不能改善 `best`，故它是全局最优。

本章结点直接复制 `selected/path/used/placed`。这使代码清晰，也使每个结点的生成成本达到 `O(n)` 或 `O(n+m)`；复杂度表必须计入该成本。生产求解器可能使用父指针、位集、增量界和专门内存池降低常数，但证明义务不变。


1. 货箱装载的上界为什么要与容量 `C` 取较小值？即使不取，算法是否仍然正确？
2. 背包的“当前价值 + 剩余总价值”界为什么安全？它在什么输入上会很松？
3. 为什么最大团不能只检查候选顶点与已选集合中的**一个**顶点相邻？
4. 旅行商若只算已走路径费用作为下界，是否仍安全？剪枝效果如何？
5. 电路板排列的前缀密度界为什么不会随排列继续增长而降低？
6. 把最佳优先队列换成普通 FIFO 队列，正确性与空间/搜索顺序分别会怎样变化？

7. 为什么入队时检查过界，出队时还要再次检查？给出队列等待期间 `best` 被改进的情形。
8. 两船装载中，若第一船未取最大可装重量，为什么不能据此断定第二船不可行？
9. 设计一个上界完全相同的背包实例，说明最佳优先队列可能退化为大量并列活结点。

**答案提示：** 上界与容量取最小会更紧但不影响安全性；只用已走 TSP 费用仍是下界，却几乎不剪枝；队列策略改变顺序，不改变安全剪枝后的解集合。
