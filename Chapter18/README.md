# 第 18 章：分而治之算法

分而治之把一个问题拆成规模更小、形式相同的子问题，递归求解后再组合答案。本章先讲设计思想与所需数据结构，再以残缺棋盘、归并排序、快速排序、选择和相邻最近的点对为例。最后解递归方程，讨论同时找最小最大值与比较排序的下限。代码在 [divideAndConquer.hpp](./divideAndConquer.hpp)，可运行示例在 [chapter18Demo.cpp](./chapter18Demo.cpp)，测试在 [testChapter18.cpp](./testChapter18.cpp)。全部兼容 C++11。

## 1. 思想、适用条件和数据结构

一个典型算法有三步：

1. **分**：把规模为 `n` 的原问题划成若干较小的同类问题。
2. **治**：对子问题递归求解；规模足够小时直接求解（递归基）。
3. **合**：利用子问题答案产生原问题答案。有的算法的“合”很复杂（归并、最近点对），有的主要工作在“分”（快速排序、选择）。

正确性通常用归纳法说明：递归基正确；假设子问题解正确，证明分解覆盖了全部情况，合并也不会遗漏跨子问题的解。分出的子问题若大量重叠，通常应考虑记忆化或动态规划。

本章用到的数据结构：

| 场景 | 关键结构 | 作用 |
| --- | --- | --- |
| 全部递归算法 | 调用栈 | 保存子问题边界、局部结果和返回位置 |
| 残缺棋盘 | `vector<vector<int>>` | 存方格；相同正整数表示同一块骨牌，`0` 表示缺格 |
| 归并排序 | 原数组和一次分配的缓冲数组 | 从两个有序区间线性合并，保持相同元素的原顺序 |
| 快速排序、选择 | 原数组中的三个连续区间 | 分别存小于、等于、大于枢轴的元素；不必另建数组 |
| 最近点对 | 按 `x` 排序的点数组、按 `y` 归并的缓冲区、带状候选区 | 只检查可能跨越分界线的点对 |

下文以 `n` 表示数组元素或点数。`O` 是渐近上界，`Ω` 是渐近下界，`Θ` 表示两者同阶；“平均”与“最坏”必须区分。

## 2. 残缺棋盘：用 L 形骨牌覆盖

**背景。** 一块 `2^k × 2^k` 的棋盘恰好缺掉一格，余下方格要用三格一块的 L 形骨牌覆盖，骨牌不能重叠或越界。剩余格数 `4^k-1` 能被 `3` 整除，但整除本身不说明一定能铺满。

**算法。** 把棋盘分成四个相同象限。缺格落在其中一个象限；在中心放一块 L 形骨牌，占据**另外三个象限**各自的中心角。于是四个象限都恰好有一个“缺格”（原来的缺格或中心骨牌占的格），递归处理。`1×1` 是递归基，无须放骨牌。通过这一归纳构造，任意合法缺格位置都能铺满。

```text
4×4 棋盘缺 (1,2)：
先找出缺格所在的右上象限；中心骨牌占左上、左下、右下的中心角；
四个 2×2 象限各放一块 L 形骨牌。
```

调用 `tileDefectiveBoard(size, missingRow, missingCol)` 返回编号矩阵；行、列从 `0` 开始。`size` 必须是正的 2 的幂，缺格必须在棋盘内。对 `n>1`，递归方程为 `T(n)=4T(n/2)+Θ(1)`，`T(1)=Θ(1)`，所以 `T(n)=Θ(n²)`；输出矩阵本身也有 `n²` 格。矩阵用 `Θ(n²)` 空间，递归栈为 `O(log n)`。

## 3. 归并排序：先排序两半，再线性合并

**背景。** 一批记录需要按键排序，且相同键的原有顺序有意义时，要用稳定排序。比如同分学生按输入顺序展示。本章接口排序 `int`；合并时左侧相等元素先输出，展示了稳定排序的关键规则。

**算法。** 平分数组，分别排序；用两个指针扫描已排序的两半，每次取较小元素写入缓冲区，再复制回原数组。递归基是长度 `0` 或 `1`。`mergeSort(values)` 原地改变传入向量，但合并需要一个长度 `n` 的辅助数组。

例如 `[5,1,3,1]` 先得到 `[1,5]`、`[1,3]`，合并为 `[1,1,3,5]`。每层合并总共扫描 `n` 个元素，`T(n)=2T(n/2)+Θ(n)=Θ(n log n)`，最好、平均、最坏都如此。辅助数组 `Θ(n)`，递归栈 `O(log n)`。

## 4. 快速排序：枢轴划分

**背景。** 当可以直接改变数组、希望通常只用少量额外空间时，快速排序是常见选择。本章选当前区间中间位置的值作枢轴，做三路划分：`< pivot`、`== pivot`、`> pivot`，只递归两侧。等于枢轴的元素不用再次处理，因而全相同输入也只做一轮划分。

例如 `[5,1,3,1,-4,8]` 以值 `1` 划分，形成 `[-4] | [1,1] | [5,3,8]`（区间内部次序取决于交换），再排序两侧。`quickSort(values)` 改变传入向量；它**不稳定**。

单次划分为 `Θ(n)`。若每次近似平分，`T(n)=2T(n/2)+Θ(n)=Θ(n log n)`；随机排列的期望时间也是 `Θ(n log n)`。若枢轴反复落在极端位置，`T(n)=T(n-1)+Θ(n)=Θ(n²)`。选中间**位置**不保证值居中，因此不能承诺最坏 `O(n log n)`。实现总是先递归较短的一侧，再用循环处理较长一侧，使最坏调用栈也为 `O(log n)`；划分用 `O(1)` 其他空间。

## 5. 选择：只找第 k 小，不排序全部

**背景。** 要求中位数、排名阈值或第 `k` 小值时，完整排序做了多余工作。`selectKth(values, k)` 以 **0 起始**的秩返回值：`k=0` 是最小值，重复元素各占一个名次。参数按值传入，因此调用者的向量不会被改动；空数组或秩越界抛出 `out_of_range`。

**算法。** 与快速排序相同，三路划分后，看目标秩处于哪个区间。若处于等于枢轴的区间，直接返回；否则只在**一个**子区间继续。例 `[5,1,3,1,-4,8]` 的第 `3` 小（`k=3`）为 `3`。

平衡划分时 `T(n)=T(n/2)+Θ(n)=Θ(n)`：工作量近似 `n+n/2+n/4+…<2n`。随机排列的期望也是 `Θ(n)`；固定位置枢轴在对抗性输入上可能每次只排除一个元素，最坏 `Θ(n²)`。由于按值传入，复制需 `Θ(n)` 空间；迭代划分本身只需 `O(1)` 空间。若需要保证最坏线性时间，可改用五组中位数枢轴，但代码会复杂得多。

## 6. 平面最近点对：别漏掉跨边界的答案

**背景。** 给定平面中的点，要找欧氏距离最小的两个不同输入点，例如找地图上最接近的两处设施。分别求左右两半的最近点对还不够：真正最近的两点可能分居分界线两侧。

**算法。** 先按 `x` 坐标排序，把点分为左右两半并递归求最近距离 `δ`。各子区间返回时按 `y` 有序，再线性归并。跨边界的更优点对只能出现在距中线不超过 `δ` 的带状区域。按 `y` 扫描该区域时，每点只需比较后续至多 7 个候选点：在一个 `δ × 2δ` 的局部窗口内，左右半区已有点间距至少 `δ`，按小方格划分可限制候选数量。这是线性检查跨边界点对的几何依据。

`closestPair(points)` 返回两个**原始输入下标**（升序）和距离；如果有多个最近点对，返回其中一个。输入至少两个点，坐标必须有限。重复坐标的两个输入点距离为 `0`。测试用的 `[-1,0]`、`[1,0]`、`[0,0.2]` 中，最近距离是 `√1.04`，跨越左右分组。距离用 `hypot` 计算以避免平方溢出；若结果本身超出 `double` 范围，则抛出 `overflow_error`。

每层按 `y` 归并和扫描均为 `Θ(n)`，所以 `T(n)=2T(n/2)+Θ(n)=Θ(n log n)`；初始按 `x` 排序也为 `Θ(n log n)`。点数组、归并缓冲和局部带状区共用 `O(n)` 额外空间；递归深度 `O(log n)`。直接枚举全部点对需要 `Θ(n²)` 时间。

## 7. 如何解递归方程

先写明**规模参数**、**递归基**、**子问题个数与大小**，再加上分解、合并的非递归工作量。不要看到两个递归调用就直接写 `O(log n)`：需要把每层全部节点的工作相加。

| 方法 | 做法 | 例子 |
| --- | --- | --- |
| 展开 / 代入 | 递推若干次，识别求和式，再用归纳验证 | `T(n)=T(n-1)+n` 展开为 `n+(n-1)+…+1=Θ(n²)` |
| 递归树 | 算每层节点数、每个节点代价及树高 | 归并排序每层工作 `Θ(n)`，共 `log₂n` 层，得 `Θ(n log n)` |
| 主定理 | 对 `T(n)=aT(n/b)+f(n)` 比较 `f(n)` 和 `n^(log_b a)` | 棋盘：`a=4,b=2,f=Θ(1)`，得 `Θ(n²)` |

主定理常见三种情况：若 `f(n)=O(n^(log_b a-ε))`，递归叶子主导，`T(n)=Θ(n^(log_b a))`；若 `f(n)=Θ(n^(log_b a) log^k n)` 且 `k≥0`，则 `T(n)=Θ(n^(log_b a) log^(k+1)n)`；若 `f(n)=Ω(n^(log_b a+ε))` 且满足通常的正则条件 `a f(n/b)≤c f(n)`（某个 `c<1`），则合并工作主导，`T(n)=Θ(f(n))`。主定理**不能直接套**到 `T(n-1)` 或快速排序的任意不等分上。

| 算法 | 递归式或工作量 | 结果 |
| --- | --- | --- |
| 残缺棋盘 | `4T(n/2)+Θ(1)` | `Θ(n²)` |
| 归并排序 | `2T(n/2)+Θ(n)` | `Θ(n log n)` |
| 快速排序 | `T(k)+T(n-k-1)+Θ(n)`；三路划分时等于枢轴区间整体跳过 | 平衡 `Θ(n log n)`；最坏 `Θ(n²)` |
| 选择 | `T(k)+Θ(n)`，仅保留目标侧 | 平衡 `Θ(n)`；最坏 `Θ(n²)` |
| 最近点对 | `2T(n/2)+Θ(n)` | `Θ(n log n)` |
| 成对比较找极值 | 每对 3 次比较，外加初始化 | `Θ(n)` |

## 8. 最小最大问题的比较下限

**问题。** 对 `n≥1` 个不同元素，同时找最小值和最大值，比较次数最少能到多少？若分开找，各需 `n-1` 次，共 `2n-2` 次。成对处理更好：每对先内部比较，小的只和当前最小值比，大的只和当前最大值比。

当 `n=2m` 时，先用 1 次比较初始化最小和最大；其余 `m-1` 对各用 3 次，共 `1+3(m-1)=3n/2-2` 次。当 `n=2m+1` 时，先把首元素作为两种极值，余下 `m` 对各用 3 次，共 `3(n-1)/2` 次。统一写作 `⌈3n/2⌉-2`（`n=1` 时为 `0`）。`findMinMax` 同时返回两个值和实际比较计数。

**为什么也是下限。** 用对抗者论证：在比较前，任意元素都可能是最小或最大；第一次比较一对元素后，败者才失去成为最大值的资格，胜者才失去成为最小值的资格。对 `2m` 个元素，至少需要 `m` 次首次配对比较，随后在 `m` 个“可能最小者”中确定最小需要 `m-1` 次，在 `m` 个“可能最大者”中确定最大再需 `m-1` 次，总计至少 `3m-2`。奇数情形留一个同时具有两种资格的元素，可得到 `3m` 次。这里讨论的是**仅通过元素间比较**且要对任意输入正确的算法；若输入有额外范围或顺序保证，模型会不同。

## 9. 比较排序的下限

对 `n` 个**互异**键，排序算法必须区分 `n!` 种输入排列。每次二元比较最多产生两个结果，所以比较过程可表示为二叉决策树；若最坏比较次数为 `h`，树最多有 `2^h` 个叶子。于是 `2^h ≥ n!`，即 `h ≥ ⌈log₂(n!)⌉ = Ω(n log n)`（由 `n! ≥ (n/2)^(n/2)` 即可看出数量级）。这也是比较排序最坏比较次数的下限，归并排序的 `Θ(n log n)` 因而在渐近意义上最优。

这个结论限定在**比较排序**。计数排序、基数排序若利用整数键的范围或位数，可以避开纯比较模型；它们也必须为额外的键范围或位数付出时间、空间成本。快速排序的平均 `Θ(n log n)` 与下限同阶，但最坏 `Θ(n²)`，所以不能称它具有最坏意义下的最优保证。
