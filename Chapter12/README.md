# 第 12 章：优先级队列、堆及其应用

本章先学“优先级队列允许做什么”，再学“堆为什么能高效做到”，接着学习适合**合并**的左高树，最后用堆完成排序、霍夫曼编码和机器调度。建议阅读顺序：第 1～6 节 → `chapter12Demo.cpp` → 第 7～10 节 → `testChapter12.cpp`。

## 1. 优先级队列：先取最重要的元素

普通队列按进入时间出队（FIFO）；优先级队列按**优先级**取出元素。最大优先级队列每次暴露优先级最高的元素。`pqueue.hpp` 中的 `maxPriorityQueue<T>` 是抽象数据类型（ADT）：

| 操作 | 含义 | 本章堆实现的成本 |
| --- | --- | --- |
| `empty()`、`size()` | 判断空、读取元素数 | `O(1)` |
| `top()` | 查看最高优先级元素，不删除 | `O(1)` |
| `push(x)` | 插入元素 | `O(log n)` |
| `pop()` | 删除最高优先级元素 | `O(log n)` |

空队列调用 `top()` 或 `pop()` 抛 `priorityQueueEmpty`。`top()` 返回对堆内元素的只读引用，随后 `push`、`pop` 或 `initialize` 可能使该引用失效；若要保留值，先复制。ADT 没承诺相同优先级元素的先后顺序，不能把它当作稳定的 FIFO 队列。

## 2. 堆到底是什么？

本章的**二叉堆**同时满足两个条件：

1. **形状条件：** 它是一棵完全二叉树。除最后一层外，每层都满；最后一层从左到右填充，没有中间空洞。
2. **顺序条件：** 最大堆的每个父结点都不小于自己的孩子；最小堆则反过来。

例如数组 `[10, 5, 3, 4, 1]` 表示：

```text
         10
       /    \
      5      3
     / \
    4   1
```

注意：`5` 与右子树的 `3` 有大小关系只是碰巧；堆只约束**父子之间**。整个数组并未排序。最大值一定在根，但第二大值只可能在根的两个孩子之一，不能直接说在数组下标 1。

完全二叉树非常适合数组。本章 `maxheap.hpp` 用**零基下标**：

```text
下标 i 的父结点： (i-1)/2       （i>0）
下标 i 的左孩子： 2i+1
下标 i 的右孩子： 2i+2
```

数组连续存储实际结点，不需要左右指针，也不会像一般二叉树的数组表示那样留下许多空槽。含 `n` 个结点的堆高度为 `⌊log₂n⌋+1`（`n>0`）；这就是上滤、下滤最多只走 `O(log n)` 层的原因。

## 3. 插入：从末尾向上滤

要插入 `12`，先把它放到数组末尾，保持完全二叉树的形状。若它比父结点更大，就交换；不断向根比较，直到父结点不小于它或已到根。

```text
原堆：       [10, 5, 3, 4, 1]
末尾加 12：  [10, 5, 3, 4, 1, 12]
12 与 3 换：[10, 5, 12, 4, 1, 3]
12 与 10 换：[12, 5, 10, 4, 1, 3]
```

为什么只需检查祖先？插入前所有其他父子关系都合法；新元素只可能破坏从新叶子到根的那条路径。`push` 的比较和交换次数最多等于堆高，因此时间为 `O(log n)`；`std::vector` 扩容另有一次性搬移成本，摊销插入仍遵循对数级比较成本。

## 4. 删除最大值：末尾补根，再向下滤

`pop()` 删除根。若直接移走根，会在完全二叉树的最前面留下洞。正确做法是取出**最后一个元素**补到根，缩短数组，再让它和较大的孩子比较；孩子更大就交换，直到堆序恢复。

```text
原堆：             [12, 5, 10, 4, 1, 3]
末尾 3 补根：      [3, 5, 10, 4, 1]
与较大孩子 10 换： [10, 5, 3, 4, 1]
```

一定要挑**两个孩子中较大的一个**。若把根与较小孩子交换，较大孩子仍可能超过新父结点，堆序就没有修好。下滤同样只沿一条根到叶路径，时间 `O(log n)`。

## 5. 初始化：为什么自底向上建堆是 `O(n)`？

`maxHeap<int> heap(values)` 或 `heap.initialize(values)` 先复制一段无序数组，然后从最后一个非叶结点 `n/2-1` 向前逐个下滤。叶子本来就是合法的单结点堆；处理某个父结点时，它的两个孩子子树已经是堆，因此一次下滤就能修好以该结点为根的子树。最终处理根，整棵树成为堆。

看起来有约 `n/2` 个结点，每次下滤最多 `O(log n)`，似乎是 `O(n log n)`；但大部分结点靠近叶子，只能下滤 0～1 层。高度为 `h` 的结点约有 `n/2^{h+1}` 个，所以总工作量与 `n·Σ(h/2^h)` 同阶，即 **`O(n)`**。逐个 `push` 建堆则是 `O(n log n)` 的上界。

`initialize(const T* values, int count)` 从 `values[0]` 开始**复制** `count` 个元素，不接管调用者的内存；这修正了旧草稿直接接管外部数组所有权的问题。`maxHeap<T, Compare>` 默认使用 `std::less<T>`，即最大堆；如果传 `std::greater<T>`，同一上滤／下滤算法会按比较器形成最小堆。

## 6. 左高树（HBLT）：把“合并”作为核心操作

前面的数组堆利用完全二叉树的形状快速定位父子结点，但合并两堆时不能简单接上另一棵树：形状和堆序都可能被破坏。**高度优先左高树**（height-biased leftist tree，HBLT）只要求树满足最大堆的父子顺序，另用一个 `s` 值保证右路径很短，因此适合合并。

这里的 `s(x)` 是从结点 `x` 沿子结点走到最近**空孩子**的最短路径所含的非空结点数，**不是普通树高**。约定 `s(空)=0`，叶子的 `s=1`。每个结点保持：

```text
s(左孩子) >= s(右孩子)          左高性质
s(本结点) = s(右孩子) + 1      左高性质下的结果
父结点的元素 >= 两个孩子的元素  最大堆性质
```

例如：

```text
           10 (s=2)
          /        \
      8 (s=2)    7 (s=1)
      /     \
  5 (s=1) 3 (s=1)
```

左子树可以很高，整棵 HBLT **不要求完全**，也不保证最长路径短；它刻意让**右路径**短。沿右孩子每走一步，`s` 恰好减 1，所以根的 `s` 就是右路径的结点数。另一方面，`s(x)=k` 的左高树至少有 `2^k-1` 个结点：左右孩子的 `s` 都至少为 `k-1`，递归应用即可。因此 `s(root) ≤ ⌊log₂(n+1)⌋`，右路径长度是 `O(log n)`。

### 合并两棵最大 HBLT

合并是最重要的原语。比较两个根，让较大根继续做根；较小根所在的树与较大根的**右子树**递归合并。返回时，如果左孩子的 `s` 小于右孩子，就交换左右孩子，最后令当前结点 `s = s(右孩子)+1`。这样只沿两棵树的右路径调整。

```text
merge(A, B):
    如果 A 空，返回 B；如果 B 空，返回 A
    如果 A.root < B.root，交换 A、B
    A.right = merge(A.right, B)
    如果 s(A.left) < s(A.right)，交换 A.left、A.right
    A.s = s(A.right) + 1
    返回 A
```

根选较大者保证**最大堆性质**；交换孩子不改变父子大小关系，却恢复**左高性质**。右路径长度均为对数级，所以合并两棵分别含 `n`、`m` 个结点的树需要 `O(log(n+m))` 时间。`maxHBLT<T>::merge(other)` 直接转移结点所有权，合并后 `other` 为空；与自身合并是空操作。两棵树必须采用**相同的比较规则**，有状态的比较器也必须有等价状态。

### 插入、删除与初始化

- **插入 `x`：** 将 `x` 看作单结点 HBLT，与原树合并。时间 `O(log n)`。
- **删除最大值：** 根就是最大值。删除根后，把原根的左、右子树合并为新树。时间 `O(log n)`。
- **初始化：** 为每个输入元素创建单结点树，放入队列；反复取出前两棵树合并，再把结果放回队列，直到只剩一棵。总共 `n-1` 次合并；小树先合并，整体建树时间 `O(n)`。`initialize` 先建新树，完成后替换旧树；数组重载从下标 0 开始**复制**输入，不接管数组所有权。

```cpp
maxHBLT<int> a(std::vector<int>{10, 4, 8});
maxHBLT<int> b(std::vector<int>{12, 5, 3});
a.merge(b);     // a 含 6 个结点，b 为空；a.top() == 12
a.push(15);     // 与单结点树合并；a.top() == 15
a.pop();        // 合并旧根的左右子树；a.top() == 12
```

`maxHBLT.hpp` 实现 `maxPriorityQueue<T>` 接口，并提供 `merge`、`initialize`、`clear`。`valid()` 会在 `O(n)` 时间检查堆序、左高性质、`s` 值与结点数，适合学习和测试；`rootS()` 返回根的 `s`，空树为 0。结点由树拥有，类禁止复制；`top()` 引用在修改树后可能失效。`clear()` 递归删除结点，调用栈与树的**实际高度**有关；左高性质只限制右路径，不限制整棵树的高度。

| 操作 | 数组最大堆 `maxHeap` | 最大 HBLT `maxHBLT` |
| --- | --- | --- |
| `top` | `O(1)` | `O(1)` |
| 插入、删除最大值 | `O(log n)` | `O(log n)` |
| 从 `n` 个元素初始化 | `O(n)`，自底向上下滤 | `O(n)`，单结点树两两合并 |
| 合并两棵现成的树 | 需重新组织元素 | `O(log(n+m))`，直接转移结点 |
| 存储 | 连续数组，无结点指针 | 每结点存左右指针和 `s` |

需要频繁合并优先级队列时，HBLT 的优势最明显；仅需不断取堆顶时，数组堆更紧凑，也更容易利用连续内存。

## 7. STL 中的优先队列与堆算法

`std::priority_queue<T>` 默认是最大优先队列。要最小优先队列，可以给第三个模板参数 `std::greater<T>`：

```cpp
std::priority_queue<int> maximums;
std::priority_queue<int, std::vector<int>, std::greater<int>> minimums;
maximums.push(4); maximums.push(9); // top() == 9
minimums.push(4); minimums.push(9); // top() == 4
```

它提供 `push`、`top`、`pop`、`empty`、`size`，但没有直接访问内部数组或批量 `initialize` 的公共接口。标准库还提供作用于**随机访问区间**的堆算法：

```cpp
std::vector<int> a{4, 10, 3, 5, 1};
std::make_heap(a.begin(), a.end());      // O(n)，把整个区间建成最大堆
a.push_back(12);
std::push_heap(a.begin(), a.end());      // 新元素已放末尾，再上滤
std::pop_heap(a.begin(), a.end());       // 最大值移到末尾；尚未从 vector 删除
int maximum = a.back();
a.pop_back();
std::sort_heap(a.begin(), a.end());      // 堆区间排序后不再保持堆形
```

`pop_heap` 与 `priority_queue::pop()` 的行为不同：前者只把最大值交换到区间末尾，调用者还需缩短容器。STL 比较器与本章 `maxHeap` 一样，表示“谁应排在后面”：默认 `less` 让最大元素成为堆顶。

## 8. 应用一：堆排序

`heapSort.hpp` 直接实现堆排序：先在原数组中 `O(n)` 建最大堆；然后把根与堆区间最后一个元素交换，将堆区间长度减 1，并对新根下滤。重复直到堆区间只剩一个元素。

```text
最大堆区间 | 已排序后缀
[最大值 ...] | []
[次大值 ...] | [最大值]
...        | [..., 次大值, 最大值]
```

默认 `std::less<T>` 得到**升序**；传 `std::greater<T>` 得到降序。时间最坏 `O(n log n)`，额外辅助空间 `O(1)`（不计输入数组）。堆排序**不稳定**：相等元素交换到根或末尾时，原来的相对顺序可能改变。其优势是最坏时间有界且无需额外的同规模数组。

## 9. 应用二：霍夫曼编码

若字符出现频率不同，常见字符可以分配短编码，少见字符分配长编码。霍夫曼编码是一种**前缀码**：任何字符的编码都不是另一个字符编码的前缀，因此从左到右读取比特即可唯一解码。

构造过程用**最小堆**保存当前树的根：

1. 每个字符建立一个叶结点，权重是出现频率。
2. 取出权重最小的两棵树，合成一棵新树，新根权重是两者之和。
3. 将新树放回最小堆，直到只剩一棵树。
4. 从根往左记 `0`、往右记 `1`，走到叶子所得路径就是该字符的码字。

经典频率 `a:5, b:9, c:12, d:13, e:16, f:45` 的带权路径长度为 **224**，即 `Σ(频率 × 码长)`。每次合并最轻的两棵树，是最优前缀码的贪心选择。若有 `k` 个不同字符，建树需 `O(k log k)` 时间；本实现编码的是**字节串**，`std::string` 中的 UTF-8 中文会被当作多个字节，而不是单个汉字。

`huffmanCoding.hpp` 提供 `codes()`、`encode()`、`decode()`、`weightedPathLength()`。只有一种字符时码字约定为 `0`；空输入得到空码表。相同频率时按字节值和结点创建顺序打破平局，因此结果可复现。编码后的 `"0"`/`"1"` 字符串用于教学；真正压缩文件还需要把比特打包成字节，并保存足以重建码表的信息。

## 10. 应用三：多机器调度

`machineScheduling.hpp` 处理一批独立作业和 `m` 台相同机器：作业不可拆分，机器同一时刻只能处理一个作业，所有作业都在时刻 0 可开始。目标是尽量缩短所有作业完成的时刻（**makespan**）。

本实现使用 LPT 规则：先按处理时间从长到短排列作业；每次从**最小堆**取最早空闲的机器，把当前作业安排在该机器空闲时刻，再把更新后的机器放回堆。机器空闲时刻相同时选编号较小者，作业时长相同时选编号较小者，便于重复演示。

例如 3 台机器处理时长 `7,6,5,4,3,2,1`：前三个作业从时刻 0 分别占用三台机器；后续作业依次放到最早空闲机器，最终完工时刻是 10。该规则产生**合法调度**，但不保证所有输入都达到全局最优。排序需要 `O(n log n)`，每个作业的取机和归队需要 `O(log m)`，初始化机器堆需 `O(m log m)`；空间 `O(n+m)`。
