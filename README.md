# DataStructure：C++ 数据结构与算法教学代码库

本仓库是一套按学习依赖组织的 C++11 数据结构与算法课程。每章把讲义、实现、演示和断言测试放在同一目录，目标是让学生不仅会调用代码，还能回答：问题为什么需要这种结构、表示不变量是什么、算法为什么正确、复杂度在什么假设下成立、边界输入怎样处理。

## 课程使用方式

每章建议按同一流程学习：

1. 阅读章节 `README.md` 的学习目标、先修知识和问题动机。
2. 对照具体数据手算讲义中的状态表、树形或队列变化。
3. 阅读 ADT，再阅读具体实现；先找表示不变量和所有权，再看算法细节。
4. 编译运行演示，预测输出后再核对。
5. 运行测试；测试无输出且退出码为 0 表示断言全部通过。
6. 完成分层练习，能独立解释正确性和复杂度后再进入下一章。

所有命令默认从仓库根目录执行，使用：

```powershell
g++ -std=c++11 -O2 -Wall -Wextra -Wpedantic -Werror <source.cpp> -o <program.exe>
.\<program.exe>
```

不要添加 `-DNDEBUG`，它会禁用本仓库测试使用的 `assert`。模板实现放在 `.hpp` 中；有独立非模板实现的程序需要同时链接对应 `.cpp`，各章讲义会给出准确命令。

## 贯穿课程的比较线索

同一个问题用不同方法求解，最能看清算法设计的取舍：

| 问题 | 章节 | 方法 | 保证与主要代价 |
| --- | --- | --- | --- |
| 0/1 背包 | 17 | 价值密度贪婪 | 快，但不保证最优；同时给出 DP 对照 |
| 0/1 背包 | 19 | 动态规划 | 精确，`O(nC)` 伪多项式时间和空间 |
| 0/1 背包 | 20 | 深度优先回溯 | 精确，线性搜索辅助空间，最坏指数时间 |
| 0/1 背包 | 21 | 最佳优先分支定界 | 精确，最坏指数时间与空间，界决定实际剪枝 |
| 无权最短路 | 9、16 | BFS | 等权边下最少边数，`O(V+E)`（邻接表） |
| 非负权最短路 | 17 | Dijkstra | 非负权下单源最短路 |
| 允许负边 | 19 | Bellman–Ford | 检测从源可达负环，`O(VE)` |
| 所有点对 | 19 | Floyd–Warshall | 允许负边、拒绝负环，`O(V³)` |
| 装箱 | 13、14 | First/Next/Best-Fit | 三种在线启发式，选择规则不同，均不承诺全局最少箱数 |

## 每章讲义的固定组成

章节讲义应能独立支撑课堂和自学，通常包含：

- 学习目标、先修知识和代码阅读顺序；
- 问题动机、ADT 规格、表示不变量和所有权；
- 至少一个使用具体数据的逐步推演；
- 正确性理由：循环不变量、归纳、交换论证、割性质或安全界；
- 基于**当前实现**的时间与空间复杂度，包括复制、排序和状态存储；
- 空输入、重复键、越界、溢出、无解、断开图、负权等边界；
- 可复制的根目录编译命令；
- 基础、推演、证明或扩展练习与答案提示；
- 与前后章节的联系，以及“已实现”和“概念介绍”的明确区分。

## 全仓库验证

安装可执行的 `g++` 与 PowerShell 后，可以运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/verify-all.ps1
```

脚本会查找所有含 `main` 的 `.cpp`，使用 C++11 和严格警告编译到系统临时目录，再逐个执行；随后逐个检查所有 `.hpp/.h` 能否独立包含。它知道第 1 章货币程序需要链接 `currency.cpp`、第 6 章程序需要链接 `binSort.cpp`。临时可执行文件不写进仓库。

也可按章运行讲义列出的精确命令。计时程序只验证能够正确编译运行，具体微秒或毫秒值不作为跨机器断言。

## 当前覆盖边界

本仓库形成了一条完整的核心课程主线，但“数据结构与算法”领域没有有限代码库能覆盖全部专题。当前实现重点是单机、内存内、教学规模的通用结构与经典设计方法。以下主题尚未作为独立章节实现：

- Trie、后缀结构、KMP 等字符串专用结构与算法；
- Fenwick 树、线段树、RMQ 等范围查询结构；
- 强连通分量、网络流、匹配、A* 等进阶图算法；
- B+ 树磁盘页、数据库并发控制、崩溃恢复和外存算法；
- 并发／无锁容器、持久化数据结构与缓存一致性；
- FFT、计算几何完整体系、随机算法与近似算法专题。

讲义只把仓库中真实存在且经过测试的内容写为“已实现”；概念扩展会明确标注。若继续扩充，应优先保证章节代码、测试、演示和讲义同时更新，而不是只增加一个孤立头文件。
