# 第 14 章：二叉搜索树（Binary Search Tree）

本章从“怎样同时方便地**按键查找**和**插入**”出发，推导二叉搜索树（BST）的结构，再逐步讲解搜索、插入、删除和高度。建议先读第 1～4 节并运行 `chapter14Demo.cpp`，再对照 `binarySearchTree.hpp` 看第 5～8 节。

## 1. 为什么会想到二叉搜索树？

我们要实现一个字典：保存“键 → 值”，按键找值、加入新键、删除旧键。前面学过两种有序存储：

| 结构 | 找位置 | 插入／删除的额外代价 |
| --- | --- | --- |
| 有序数组 | 可以二分，`O(log n)` | 为保持连续顺序，移动元素，最坏 `O(n)` |
| 有序链表 | 必须顺着指针找，`O(n)` | 找到位置后改链接是 `O(1)` |

能否把**二分搜索的分支选择**和**链式结点的局部修改**结合起来？把一个键放在根；比根小的键放左边，比根大的键放右边。每个子树也遵守同一规则，于是查找时每比较一次，就能舍弃另一整棵子树；插入时走到一个空孩子位置，接上新结点即可。这就是二叉搜索树的设计思路。

例如按 `8,3,10,1,6,14,4,7,13` 插入：

```text
          8
        /   \
       3     10
      / \      \
     1   6      14
        / \     /
       4   7   13
```

每个结点都必须满足 **左子树所有键 < 本结点的键 < 右子树所有键**。这是 BST 的不变量，不只比较直接孩子。由此也能推出：**中序遍历**（左、根、右）会按键递增输出 `1,3,4,6,7,8,10,13,14`。

## 2. 抽象数据类型与本章代码

`binarySearchTree<K,E,Compare>` 实现仓库 `Chapter10/dictionary.hpp` 的 `dictionary<K,E>` ADT。它的结点保存 `std::pair<const K,E>` 和左右指针。键 `K` 不可在树中直接改动，因为改键可能破坏 BST 顺序；值 `E` 可以更新。

| 操作 | 约定 |
| --- | --- |
| `empty()`、`size()` | 判断空树、读取数对个数 |
| `find(key)` | 找到时返回数对指针，找不到返回 `nullptr` |
| `insert({key,value})` | 新键接入叶位置；已有键更新值，不增加结点数 |
| `erase(key)` | 删除该键；键不存在时不改变树 |
| `height()` | 空树为 0，单结点树为 1，按结点层数计高度 |
| `inOrder(visit)` | 按键升序访问数对 |
| `clear()` | 删除整棵树 |

默认比较器是 `std::less<K>`，只需提供严格弱序，不要求 `K` 有 `operator==`。两个键等价的判断是 `!less(a,b) && !less(b,a)`。传自定义比较器可以改变排序规则，但同一棵树的比较规则必须始终一致。

`find` 沿用已有字典 ADT 的签名：即使在 `const` 树上，也返回可修改**值**的数对指针；`first` 是 `const K`，键仍不能改。这个指针由树拥有；删除对应结点、清空或销毁树后失效。为避免两个对象同时拥有同一批结点，本实现禁止复制。

## 3. 搜索：每次比较只走一边

例如找键 `7`：先与根 `8` 比，`7<8`，走左边；再与 `3` 比，`7>3`，走右边；再与 `6` 比，继续走右边，找到 `7`。找 `5` 则会沿 `8→3→6→4` 走到空位置，返回 `nullptr`。

```text
current = root
while current 非空:
    若 key < current.key：走左孩子
    否则若 current.key < key：走右孩子
    否则：找到等价键
走到空位置：键不存在
```

**为什么可以舍弃一边？** 若目标小于当前键，当前结点的右子树所有键都更大，目标不可能在那里；大于时同理。搜索只走一条根到结点或空位置的路径，成本是 `O(h)`，`h` 为树高。

## 4. 插入：搜索失败的位置就是新结点的位置

插入键 `5` 时，沿搜索路径 `8→3→6→4` 前进，最后应当进入结点 `4` 的右空孩子；在这里接入 `5`，仍满足整个 BST 顺序。若找到等价键，例如已有 `6`，只更新对应的值。

代码中的 `Node** link` 指向当前子树的**入口指针**，可能是根指针，也可能是某个结点的左／右孩子指针。每次向左或向右时让 `link` 改为那个孩子指针；找到空入口后，`*link = new Node(item)`。这样根为空和普通孩子为空都用同一套逻辑处理，不必额外记录父结点。

插入也只走一条路径，比较成本 `O(h)`，新结点本身占 `O(1)` 空间。先找到空位置、再分配结点；若构造结点失败，树保持原状。

## 5. 删除：关键是保持左右两边的大小关系

先像搜索一样找到目标，再区分三种情况：

1. **没有孩子（叶子）：** 把父结点指向它的入口设为空，再释放结点，例如删除图中的 `1`。
2. **只有一个孩子：** 把父入口直接改指向该孩子，例如删除 `14` 后，让原来指向 `14` 的入口直接指向 `13`。这一子树中的键本来就在正确范围内。
3. **有两个孩子：** 不能简单把左或右孩子提上来，否则另一边可能无处安放。选择目标的**中序后继**：右子树中最小的结点。它大于左子树所有键，又不大于原右子树其他键，适合接替目标的位置。

在上图删除 `3`，其右子树最小键是 `4`；沿右子树一直向左就能找到。后继 `4` 不可能有左孩子，否则它就不是右子树最小的结点；它若有右孩子，先让原位置的父入口接上这个右孩子。随后把原结点 `3` 的左右子树接到 `4` 上，最后让原来指向 `3` 的入口指向 `4`。后继若正好是目标的直接右孩子（如删除根 `8`，后继 `10`），同一段代码也适用。

这里**移动结点链接**，不执行 `target.key = successor.key`。原因是数对的键类型是 `const K`，不能赋值；而且保持原数对对象的身份更符合字典接口。删除后的中序顺序仍严格递增。定位目标和后继都只沿树路径，时间 `O(h)`；不存在的键不改变树。

## 6. 高度与性能：形状比结点数更重要

`height()` 用队列逐层遍历：先把根入队；每次处理当前队列中的整层结点，并把下一层的孩子入队；处理过的层数就是高度。它需要 `O(n)` 时间，额外队列空间为 `O(最大层宽)`。空树返回 0。

搜索、插入、删除的成本都由高度 `h` 决定：

| 形状 | 高度 | 搜索／插入／删除 |
| --- | --- | --- |
| 较均衡 | `O(log n)` | `O(log n)` |
| 退化成链 | `O(n)` | `O(n)` |

例如依次插入 `1,2,3,4,5`，每个新键都比当前结点大，树会成为一条右链，高度为 5。**普通 BST 不自动平衡**，所以不能无条件宣称它的操作都是 `O(log n)`；后面学习 AVL、红黑树等自平衡搜索树时，才会看到如何限制高度。与第 12 章的堆也要区分：最大堆可快速找最大值，却不能据堆序快速查找任意键；BST 可沿大小关系搜索任意键并按序遍历。

## 7. 使用示例

```cpp
#include "binarySearchTree.hpp"
#include <string>

binarySearchTree<int, std::string> students;
students.insert({8, "Wang"});
students.insert({3, "Li"});
students.insert({10, "Chen"});
students.insert({3, "Zhao"}); // 更新键 3 的值，size 仍为 3

auto* item = students.find(3);
if (item) item->second = "Liu";
students.erase(8);
int h = students.height();
```

若按 `dictionary<K,E>&` 使用该对象，可调用 ADT 的 `find/insert/erase/size/empty`；`height`、`inOrder`、`clear` 是具体 BST 提供的扩展操作。`testChapter14.cpp` 还演示了只有自定义比较器、没有 `operator==` 或默认构造函数的键和值。
