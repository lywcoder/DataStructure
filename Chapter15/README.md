# 第 15 章：AVL 树、红黑树与 B 树

本章在第 14 章普通 BST 的基础上，讲解几种限制树高的方法：AVL 用高度差约束，红黑树用颜色与黑高约束，B 树让一个结点保存多个有序键并保持所有叶子同层。三者都实现字典 ADT。

## 学习目标与阅读路线

先修知识是 [第 10 章的字典接口](../Chapter10/README.md)、[第 11 章的二叉树](../Chapter11/README.md) 和 [第 14 章的 BST](../Chapter14/README.md)。开始前应能画出 BST 删除叶子、单孩子和双孩子结点的过程，并理解指针指向结点不等于拥有结点。

学完后应能独立完成以下任务：

1. 区分“搜索顺序正确”和“树高受限”，检查一棵树是否同时满足两者。
2. 根据高度差选择 AVL 单旋或双旋，解释删除为什么可能一路修复到根。
3. 用黑高而非外观判断红黑树，逐项解释删除修复中的兄弟、近侄和远侄。
4. 给定阶数 `m`，推导 B 树占用下限，并模拟上溢、借位、合并、根收缩。
5. 区分键比较、结点访问、数组搬移与验证函数的实际成本。

建议先读 [`avlTree.hpp`](./avlTree.hpp) 的 `rebalance`，再读插入和删除；随后读 [`redBlackTree.hpp`](./redBlackTree.hpp) 的旋转、`fixInsert`、`fixErase`；最后读 [`bTree.hpp`](./bTree.hpp) 的 `position`、`splitNode`、`repairChild`。每学完一种结构，先手算，再运行对应测试，最后用演示比较三种高度。

三个类维护的是唯一键字典：比较器必须形成严格弱序，`!less(a,b) && !less(b,a)` 才是这里的键等价。重复插入更新值，不会增加一个副本。后文使用数值升序举例；自定义降序比较器下的“最小”和 `lowerBound` 都应按比较器顺序理解。

## 1. AVL 树：在 BST 顺序上限制高度

普通 BST 按 `1,2,3,...` 插入会成为一条链。AVL 仍按 BST 规则保存键，却要求**每个结点**的左右子树高度差不超过 1。`avlTree.hpp` 实现与普通 BST 相同的字典 ADT，另提供 `lowerBound`、`height`、中序遍历和 `clear`。它独立于索引 BST，本章 AVL 结点不保存排名信息。

### 结点、高度和平衡因子

每个结点保存 `(const 键, 值)`、`left`、`right` 和 `height`。本章约定空树高 0、叶子高 1；每次孩子链接改变后，都重新计算 `height(x)=1+max(height(x.left),height(x.right))`。定义 `BF(x)=height(x.left)-height(x.right)`，合法值为 `-1、0、1`。若变成 `2` 或 `-2`，就要旋转。`height()` 只读取根结点记录的高度，因此为 `O(1)`；测试辅助方法 `valid()` 会逐结点核对键序、记录高度和 `BF`，需 `O(n)`。

### 为什么旋转不破坏搜索顺序？

设 `y` 是 `z` 的左孩子，`T₂` 是 `y` 原来的右子树，键序为 `T₁ < y < T₂ < z < T₃`：

```text
右旋前：        z                 右旋后：       y
              / \                             / \
             y   T₃                          T₁  z
            / \                                 / \
           T₁  T₂                              T₂  T₃
```

右旋把 `y` 提上来，`T₂` 接到 `z` 左边，所以上述中序次序完全不变。左旋是镜像操作。代码先更新下降结点 `z` 的高度，再更新新根 `y`，因为后者的高度依赖前者。

| 插入路径 | 例子 | 修复 |
| --- | --- | --- |
| LL | `30,20,10` | 对失衡结点右旋 |
| RR | `10,20,30` | 对失衡结点左旋 |
| LR | `30,10,20` | 先对左孩子左旋，再对失衡结点右旋 |
| RL | `10,30,20` | 先对右孩子右旋，再对失衡结点左旋 |

判断时先看失衡结点的 `BF`，再看较高孩子的 `BF`：例如根左高 2、左孩子右倾（`BF<0`）就是 LR。双旋由两次保持键序的单旋组成。

### 插入与删除如何回溯？

插入仍先沿 BST 路径找到空位置；已有键只更新值。递归返回时，逐层更新高度并修复失衡。插入只会让祖先高度增加，修复最低的失衡祖先后，整体高度恢复，余下祖先仍会被检查。

删除先处理叶子、单孩子、双孩子三种 BST 情况。双孩子时摘取右子树最小的**后继结点**来接替目标，因此无需给 `const` 键赋值。摘取后继的路径和目标到根的路径都要回溯并可能旋转。删除可能让子树高度连续下降，所以**不能在修复第一个失衡祖先后停止**。删除时较高孩子的 `BF` 可能为 0，此时也使用相应的单旋；`testAVLTree.cpp` 覆盖了这两个对称情况。

### AVL 删除的完整局部推演

依次插入 `4,2,5,1,3` 得到左图，删除 `5` 后根的左右高度从 `(2,1)` 变为 `(2,0)`：

```text
删除前                 删除 5 后               对 4 右旋后
       4                      4                       2
      / \                    /                       / \
     2   5                  2                       1   4
    / \                    / \                         /
   1   3                  1   3                       3
```

| 检查位置 | 左高 | 右高 | BF | 动作 |
| --- | ---: | ---: | ---: | --- |
| 删除后的结点 4 | 2 | 0 | 2 | 需要修复 |
| 它的左孩子 2 | 1 | 1 | 0 | 不做左孩子左旋 |
| 右旋后的旧根 4 | 1 | 0 | 1 | 记录高度 2 |
| 新根 2 | 1 | 2 | -1 | 记录高度 3 |

这里左孩子不左倾也不右倾，但仍应单旋。若把插入场景中的“孩子 BF 必须等于 1”照搬过来，就会漏掉删除特有的 `BF=0`。

双孩子删除再看 `8`，其左子树根为 `4`，右子树为 `12`、左孩子 `10`。`detachMin` 把结点 `10` 从 `12` 左侧摘下，先修复 `12` 的高度，然后把 `10` 接到原来 `8` 的位置。最后删除的是原 `8` 的对象；原来指向 `10` 数对的指针仍指向同一对象。这是移动结点与复制后继键值的区别。

递归函数返回的是**修复后子树的新根**。父结点必须写回 `left/right`，公开入口必须写回 `root_`。只调用旋转却丢弃返回指针，会使树链接丢失，即使旋转函数内部的高度计算完全正确也无济于事。

### AVL 正确性的归纳结构

把递归契约写成：“输入子树除本次改动路径外均合法；返回的子树包含正确键集、满足 BST 顺序、记录高度正确、所有 BF 合法。”

- 递归基插入叶子或删除空位置显然满足契约。
- 递归返回后，两个孩子已经合法，因此只有当前结点可能失衡。
- 单旋保留中序顺序；双旋是两个这样的操作。高度按依赖顺序重算后，局部重新合法。
- 把新根返回上一层，就把局部结论推广到整棵树。

这也是 `valid()` 应同时查顺序与高度的原因：仅检查中序递增只能证明 BST 顺序，不能证明仍是 AVL。

AVL 的高度为何是 `O(log n)`？高度为 `h` 的 AVL 树若想使用最少结点，两个孩子的高度分别只能是 `h-1` 和 `h-2`，因此 `N(h)=1+N(h-1)+N(h-2)`。该数量随 `h` 指数增长，反过来高度只能随结点数对数增长。故查找、`lowerBound`、插入和删除最坏均为 `O(log n)`；插入和删除的递归调用栈为 `O(log n)`。

```cpp
avlTree<int, std::string> tree;
for (int key = 1; key <= 15; ++key)
    tree.insert({key, "value"});
// 普通 BST 此时高度为 15；AVL 会保持对数级高度。
tree.erase(8);
```

## 3. 为什么还要学红黑树？

AVL 把每个结点的左右高度差限制到 1；红黑树允许形状更灵活，但用一组颜色规则控制最长路径。两者都是二叉搜索树：**左边的键小于当前键，右边的键大于当前键**。因此查找和中序遍历的思路与普通 BST 完全一样，区别在插入、删除后如何维护平衡。

`redBlackTree<K,E,Compare>` 继承 `dictionary<K,E>`，提供 `empty`、`size`、`find`、`insert`、`erase`；还提供 `lowerBound`、`inOrder`、`height`、`clear` 和教学用的 `valid`。例如：

```cpp
#include "redBlackTree.hpp"

redBlackTree<int, std::string> scores;
scores.insert({8, "A"});
scores.insert({3, "B"});
scores.insert({8, "C"}); // 已有键只更新值；元素数量仍是 2
auto* found = scores.find(8); // 找到 (8, "C")；未找到则为 nullptr
scores.erase(3);
```

键通过 `Compare` 定义先后；两个键互不小于对方时视为同一个键。结点保存 `std::pair<const K,E>`、左右孩子、父结点和颜色。树拥有结点，禁止复制；`find` 返回指向树内数对的非拥有指针，删除该结点或清空树后不能再使用。`height()` 按结点层数计算，空树为 0；红黑树没有像 AVL 那样在每个结点保存高度，所以此方法需遍历整棵树，时间 `O(n)`。

## 4. 红黑性质：颜色如何限制高度

把每个空孩子想成一个**黑色的空叶子**，它不是存储键的真实结点。合法的红黑树满足：

1. 每个真实结点是红色或黑色；根是黑色，空叶子也是黑色。
2. 红结点的两个孩子必须是黑色；所以不可能连续出现两个红结点。
3. 从同一个结点到它下面任意空叶子的路径，经过的**黑结点数相同**，这个数量叫黑高。

例如下面的 `B` 表示黑色、`R` 表示红色；每条到空叶子的路径都有相同黑高：

```text
          8B
         /  \
       3R   12R
      / \    / \
     1B 6B 10B 14B
```

不能只数真实结点的黑色数量却忘记空叶子。不过每条路径都会多算同一个末端空叶子，因此比较两条路径是否相等时，也可以统一不计它。

若从根到空叶子的最短路径含 `b` 个**真实黑结点**（不计末端空叶子），最长路径因“红结点不能相邻”，长度最多约为它的两倍。黑高为 `b` 的子树至少有 `2^b - 1` 个真实结点；因此树高至多为 `2 log₂(n+1)`，查找、插入、删除的最坏时间都是 `O(log n)`。`valid()` 是遍历核对，时间 `O(n)`，不用于普通查询。

## 5. 搜索：仍然按 BST 的方向走

从根开始比较目标键：目标更小就走左孩子，更大就走右孩子，等价则返回当前数对。走到空孩子说明不存在。`lowerBound(key)` 则要找最小的、不小于 `key` 的键：遇到不小于目标的结点，先记为候选，再继续向左找更紧的答案。搜索时**不需要查看颜色**；红黑性质只保证路径不会太长。

## 6. 插入：先按 BST 接入，再修复红红冲突

先按键序找到空位置，新结点初始为**红色**。这样通常不会改变各路径黑高；若父结点也是红色，就产生“红父红子”冲突。已有键只更新值，不添加结点，也不改颜色。

```text
例：依次插入 10、5、1

插入 1 后：       10B          修复后：       5B
                /                          /  \
              5R                         1R  10R
             /
           1R
```

设新结点为 `x`、父为 `p`、祖父为 `g`，叔父是 `g` 的另一侧孩子：

| 情况 | 操作 | 为什么 |
| --- | --- | --- |
| `p` 是黑色 | 不用修复 | 没有连续红结点，黑高未变 |
| `p` 与叔父都是红色 | 父、叔染黑，祖父染红，再从祖父向上检查 | 各路径新增和减少的黑色数抵消；冲突可能上移 |
| `p` 红、叔父黑，`x` 与 `p` 方向相反 | 先围绕 `p` 旋转，变为同向 | 例如 LR 先左旋，RL 先右旋 |
| `p` 红、叔父黑，同向 | 父染黑、祖父染红，再围绕祖父旋转 | 例如 LL 右旋，RR 左旋 |

空叔父按黑色处理。旋转只改局部父子链接，不改变中序键序；最后强制把根染黑。沿祖先路径修复，最多走树高的级数。

## 7. 删除：少了一个黑结点怎么办？

先像 BST 一样找到目标。若它有两个孩子，找右子树最小的**后继结点**，把后继结点移动到目标位置；这样无需给 `const K` 键赋值。真正从原位置摘掉的结点最多只有一个非空孩子。删除不存在的键不做事。

- 摘掉红结点：它没有承担黑高，通常无需修复。
- 摘掉黑结点，且由红孩子接替：把接替者染黑，补回缺失的黑色。
- 摘掉黑结点，接替位置是黑孩子或空叶子：该路径暂时少一个黑色。代码从接替位置向上修复，常把它想成携带一个“额外的黑色”。

下面以接替位置在父结点**左边**为例；右边是镜像。它的兄弟是父结点的右孩子：

| 兄弟的情况 | 修复动作 |
| --- | --- |
| 兄弟红 | 兄弟染黑、父染红，围绕父左旋，转成兄弟黑的情况 |
| 兄弟黑，两个孩子也黑 | 兄弟染红；缺少的黑色上移到父结点 |
| 兄弟黑，靠近接替位置的孩子红、远端孩子黑 | 先围绕兄弟右旋，转成远端孩子红 |
| 兄弟黑，远端孩子红 | 兄弟继承父颜色、父与远端孩子染黑，围绕父左旋，修复结束 |

若兄弟是空叶子，按黑色且孩子也黑来处理。每次旋转都保持 BST 键序；重新着色用于恢复红黑规则和相等黑高。代码显式传入空接替位置的父结点，因为 `nullptr` 本身没有 `parent` 指针。删除后的修复可能沿路径继续向根传播，复杂度为 `O(log n)`。

### 用一个黑叶删除看清“额外黑色”

下面是合法红黑树；每条根到空孩子的路径黑结点数相同：

```text
删除 5B 前                摘掉 5B 后                修复后
       10B                      10B                      15B
      /   \                    /   \                    /   \
    5B    15B                 x    15B                10B   20B
            \                       \
            20R                     20R
```

`x` 是原 `5` 位置的空孩子，并没有真的创建一个带双重颜色的结点。它的兄弟 `15B` 为黑色，远侄 `20R` 为红色，因此直接进入表中最后一类：兄弟继承父颜色，父染黑，远侄染黑，对父左旋。

数黑高验证：修复前从 `10` 走左侧只到一个空黑叶，右侧还经过 `15B`；修复后新根两侧分别经过 `10B`、`20B`，两侧黑高一致。修复既补了左边的黑高，又没有破坏右边内部路径的一致性。

若原树只有 `10B` 的两个黑孩子 `5B,15B`，删 `5B` 时兄弟两个孩子都黑，于是把 `15` 染红，亏损上移到根，最后根吸收这份亏损。树的公共黑高减少 1 是合法的；要求是**同一结点下面各路径相等**，并不是删前删后的黑高永远不变。

### 删除修复最容易混淆的三个对象

| 对象 | 作用 | 双孩子删除时是否可能不同 |
| --- | --- | --- |
| 用户请求删除的 `target` | 最终释放的对象 | 是 |
| 从原位置摘下的后继 | 移到目标位置，其原颜色决定是否缺黑 | 是 |
| 接替后继原位置的 `replacement` | 从此位置开始修复，可为空 | 是 |

后继移到目标位置时继承目标颜色，但修复判断必须保留**后继被摘前的颜色**。否则会把目标颜色误当成真正减少的黑色，导致漏修或多修。

“近侄”“远侄”是相对亏损位置定义的：亏损在左，则兄弟左孩子近、右孩子远；亏损在右，左右互换。兄弟红的情况只是先转换形态；近红远黑的情况也是为最后的远红情况做准备。记住转换目的，比把四张图机械背成孤立公式更可靠。

红黑树旋转还要维护三个方向的关系：孩子指针、孩子的 `parent`、祖父指向新根的指针。如果旋转发生在整树根处，还必须更新 `root_`。测试中的 `valid()` 会核对父链接、严格键序、根颜色、红红冲突、黑高与结点数。

## 8. 对比与动手验证

| 结构 | 平衡依据 | 查找／插入／删除 | 本章的高度查询 |
| --- | --- | --- | --- |
| AVL | 每个结点左右高度差不超过 1 | 最坏 `O(log n)` | 读取根所记高度，`O(1)` |
| 红黑树 | 红结点不相邻、各路径黑高相同 | 最坏 `O(log n)` | 遍历计算，`O(n)` |

自己试着依次插入 `10、5、1`，画出修复前后的颜色；再从修复后的树删去 `1`，检查每条路径的黑高。可用 `chapter15Demo.cpp` 观察升序插入与删除，用 `testRedBlackTree.cpp` 核对空树、重复键、三种删除形状、自定义键类型、随机操作和升序极端输入。

## 9. 简单认识分裂树（伸展树）

这里的“分裂树”指**伸展树**（Splay Tree）：它仍是二叉搜索树，但每次访问后通过旋转把访问到的结点移近根，通常直接移到根。若访问热点集中，常访问的键就容易靠近上层。旋转分为只剩父结点的 `zig`、结点与父及祖父同向的 `zig-zig`、方向相反的 `zig-zag`。它没有 AVL 的逐点高度差规则，也没有红黑树的颜色规则；**单次**操作可能是 `O(n)`，一串操作的**均摊**成本为 `O(log n)`。本章只作概念铺垫，下面重点学习多路搜索的 B 树。

## 10. 从二叉搜索树走向 m 叉搜索树

二叉搜索树一个结点只有一个键，于是把数轴分成“左边”和“右边”。m 叉搜索树允许一个结点最多有 `m-1` 个**递增**的键，把键域分成最多 `m` 段。例如一个结点是 `[10 | 20 | 30]`：

```text
孩子位置：       C0     10     C1     20     C2     30     C3
键的范围：     <10         (10,20)      (20,30)       >30
```

查找 `25` 时，在结点内判断它位于 `20` 与 `30` 之间，再进入 `C2`；找到与某个键等价的项就停止。含 `q` 个键的内部结点恰有 `q+1` 个孩子；叶子没有孩子。若只要求这些键区间规则，树仍可能一边倒，**m 叉搜索树本身没有高度保证**。下面实现的 B 树是满足额外占用量与等深约束的 m 叉搜索树。

## 11. m 阶 B 树与结点结构

本章把“阶 `m`”定义为**最多 `m` 个孩子**，构造时要求 `m >= 3`。这和某些资料把“最小度数 `t`”作为构造参数的写法不同；阅读公式时先确认使用的是哪一种定义。记 `t = ⌈m/2⌉`：

| 结点类型 | 键数 | 孩子数 |
| --- | --- | --- |
| 根为唯一结点 | `1 ... m-1` | `0` |
| 非叶根 | `1 ... m-1` | `键数 + 1`，至少 2 |
| 非根结点 | `t-1 ... m-1` | 叶子为 0；内部为 `键数 + 1` |

**所有实际存键的叶子都在同一层。** 空树单独允许，高度记 0；单结点树高度记 1。结点示意：

```text
结点：[ (k0,v0) | (k1,v1) | ... ]   // 键递增
孩子：[     c0      |     c1      | ... | cq ]
```

`bTree.hpp` 的 `Node` 使用 `entries` 保存数对、`children` 保存子结点。数对和子结点由 `std::unique_ptr` 持有，不需要键或值提供默认构造函数。分裂、借位、合并时移动的是数对的所有权，**不会给 `pair<const K,E>` 的键赋值**。B 树结点可含多个键，不能把“结点数”误认为“字典元素数”；`size()` 统计的是键值对。`find` 和 `lowerBound` 返回树内数对指针；删除该项、`clear()` 或销毁树后不能使用。

## 12. B 树有多高？

设总共有 `n>0` 个键，高度 `h` 按真实结点层数计算。若每层尽可能满，最多能放 `m^h - 1` 个键，所以 `h >= ⌈log_m(n+1)⌉`。若每个非根结点仅放最少的 `t-1` 个键，根至少有两个孩子，则至少有 `2t^(h-1)-1` 个键，所以 `h <= 1 + log_t((n+1)/2)`。合起来，B 树高度是 `O(log_m n)`（固定阶数时也记为 `O(log n)`）。

例如 5 阶 B 树的非根结点至少有 `⌈5/2⌉-1=2` 个键，最多 4 个键。阶数变大，单个结点能装更多键，树的层数通常减少；与此同时，在一个结点内查找和移动的工作也会增加。

## 13. 搜索：先在结点内定位，再选孩子

代码在每个结点的有序键数组中**二分**，找到第一个不小于目标键的位置 `i`：若键相等就返回数对；否则若是叶子则失败，若是内部结点则进入 `children[i]`。`lowerBound` 在向下走时记录当前结点中第一个不小于目标的候选，之后在子树中继续找更小的可用键。

```cpp
#include "bTree.hpp"

bTree<int, std::string> index(5); // 5 阶，最多 5 个孩子、4 个键
index.insert({20, "B"});
index.insert({10, "A"});
index.insert({30, "C"});
auto* found = index.find(20);     // 找到 (20, "B")
auto* next = index.lowerBound(21); // 找到 (30, "C")
```

单次搜索访问 `O(h)` 个结点，每个结点二分需 `O(log m)` 次比较，总比较次数为 `O(h log m)`。这是**内存中的教学实现**；若结点对应磁盘页，更关心的是访问多少层／页。

## 14. 插入：叶子上溢就把中间键送上去

先搜索目标键。已有等价键时只更新值，不增加元素数。新键按区间走到叶子并插入有序位置。结点最多允许 `m-1` 个键；若插入后有 `m` 个键，就**分裂**：把中间键提升到父结点，左右两半各成为一个结点。父结点若也上溢，继续向上；根若分裂，就新建一个根，高度加 1。

```text
以 5 阶为例，原结点已有 4 个键： [10 | 20 | 30 | 40]
插入 50 后上溢：                 [10 | 20 | 30 | 40 | 50]
中间键 30 上升：                 父结点加入 [30]
分裂后的两个孩子：               [10 | 20]    [40 | 50]
```

这里 `t=3`，分裂后的两个非根结点都恰有至少 `t-1=2` 个键。实现先允许结点**暂时**上溢到 `m` 个键，再从下往上分裂；这也适用于奇数阶与偶数阶。搜索和分裂沿一条根到叶路径进行，结点内移动 `O(m)` 个指针，因此总时间 `O(mh)`，额外递归空间 `O(h)`。

## 15. 删除：借位、合并和根收缩

如果目标在叶子，直接删除；如果目标在内部结点，用右侧子树的**最小键（中序后继）**接替，再从那个子树移除后继。此后，某个非根结点可能只剩 `t-2` 个键，发生**下溢**：

1. 左兄弟若多于 `t-1` 个键：父结点分隔键下降到当前结点，左兄弟最大键上升到父结点；必要时同时移动一个孩子。
2. 否则右兄弟若有富余：对称地借右兄弟最小键，父分隔键下降；必要时移动孩子。
3. 两侧都没有富余：把当前结点、一个兄弟和父结点的分隔键**合并**。父结点可能继续下溢，递归向上修复。
4. 若根被合并到只剩一个孩子，那个孩子成为新根，高度减 1。

以 5 阶为例，根 `[30]`，左右叶子 `[10|20]`、`[40|50|60]`。删 `10` 后，左叶只剩一个键，低于下限 2；右叶可借出 `40`，于是变为：

```text
             [40]
           /      \
       [20|30]  [50|60]
```

若右叶原本只有 `[40|50]`，就不能借；删除后左右叶与根的 `30` 合并为 `[20|30|40|50]`，原根消失，树高减 1。借位与合并都保持各孩子的键区间和叶子等深。一次删除只在一条路径上修复，时间 `O(mh)`、递归空间 `O(h)`；不存在的键保持树不变。

### 为什么先删除再修复适合这里的阶数定义？

设非根最少键数 `k=ceil(m/2)-1`。发生一次下溢的结点有 `k-1` 个键，不能借位的兄弟有 `k` 个键，加上父分隔键，合并后键数为：

```text
(k-1) + 1 + k = 2k
m 为奇数 2r+1：k=r，合并后 2r=m-1，恰好满。
m 为偶数 2r：  k=r-1，合并后 2r-2=m-2，不会超上限。
```

若不加区别地照搬“下降前合并两个最少占用孩子”，则是 `k+1+k=2k+1`。奇数阶时会得到 `m` 个键，反而上溢。因此必须同时核对教材的参数是“最大孩子数 m”还是“最小度数 t”，以及代码采用自顶向下还是自底向上的修复。

### 借位并不是兄弟直接送一个键

沿用根 `[30]`、左 `[10|20]`、右 `[40|50|60]`，删除 `10` 的状态依次是：

| 步骤 | 父 | 左孩子 | 右孩子 | 不变量检查 |
| --- | --- | --- | --- | --- |
| 删除前 | `[30]` | `[10,20]` | `[40,50,60]` | 占用和范围合法 |
| 删除后 | `[30]` | `[20]` | `[40,50,60]` | 左孩子下溢 |
| 父键下降、右最小上升 | `[40]` | `[20,30]` | `[50,60]` | 左边全小于 40，右边全大于 40 |

如果把 `40` 直接放进左孩子却让父仍为 `30`，左孩子就包含大于父的键，违反搜索区间。对于内部结点，还要把右兄弟最左侧孩子移为当前结点最右侧孩子；它的键正处于下降键与新分隔键之间。

合并时所有叶子的深度暂时不变，只是同层结点合为一个。只有空根被唯一孩子替换，才统一让所有叶子深度减 1，因此等深性质保持。

## 16. 实现成本、所有权与适用边界

以下假设键比较、数值赋值和指针搬移为 `O(1)`；长字符串或大型值对象需另计操作成本。`n` 表示键数，B 树高为 `h`。

| 操作 | AVL | 红黑树 | 本章 B 树 |
| --- | --- | --- | --- |
| 查找、下界 | 最坏 `O(log n)` | 最坏 `O(log n)` | `O(h log m)` 比较 |
| 插入、删除 | 最坏 `O(log n)` | 最坏 `O(log n)` | 最坏 `O(mh)`，含向量搬移 |
| 读取高度 | `O(1)` | `O(n)` | `O(h)`，沿最左路径 |
| 中序、验证、清空 | `O(n)` | `O(n)` | `O(n)` |
| 插删辅助栈 | `O(log n)` | 迭代修复 `O(1)` | `O(h)` 递归栈 |

B 树分裂还会分配容纳 `O(m)` 指针的新结点缓冲，这属于新树存储以及分配期间的临时成本，不能把“递归栈 O(h)”误读为全部分配只有 O(h)。全树存储按实际键与孩子计为 `O(n)`；B 树阶数变化时，向量容量和分配常数也变化。

三个类都禁止复制。AVL、红黑树手动析构拥有的结点；B 树用 `unique_ptr` 表达所有权。查询返回非拥有数对指针，可以更新 `second`，不能修改 `const first`；删除对应项、清空或销毁树会使指针失效。旋转、B 树键指针搬移不需要移动数对对象，但这不是可以跨任意容器操作滥用指针的理由。

测试覆盖空树、重复键、查找下界、不同删除形态、不可默认构造的键值、随机与 `std::map` 对照、升序插入和连续删除。B 树还覆盖多种奇偶阶与降序比较器。随机测试能发现许多链接错误，不能替代不变量证明；当前实现也不宣称对任意会抛异常的用户比较器/值赋值或分配失败提供强异常保证。

这些是内存教学结构，不是可直接替换数据库索引的持久化实现。B+ 树的叶子链、磁盘页布局、并发锁和崩溃恢复未实现；伸展树也仅介绍概念，不应把它列为已实现的数据结构。
